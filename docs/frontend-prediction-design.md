# Breeze 前端分支预测与取指改进设计

本文记录新版 Breeze v1 前端的改动：BTB 改为只分配跳转分支、全局历史改为 S3 推测更新加检查点修复、新增返回地址栈（RAS）并在 S1 预测返回、L1I 顺序下一行预取，以及预测器参数。供微架构审阅，审阅固定后再编写 RTL 级 spec；本文不代表已经实现或验证。

后端的级划分与提交规则见 [`backend-pipeline-design.md`](backend-pipeline-design.md)。前端取指流水的级划分和 fetch buffer 不变；L1I 扩为 16 KiB、4 路（几何见 [`dcache-pipeline-design.md`](dcache-pipeline-design.md) 第 1 节）。

## 1. 现状

前端取指为 S1（查 BTB/PHT）→ S2（取指响应）→ S3（miniDecode 校正、送入 fetch buffer），fetch buffer 6 项，分支在后端 EXE 解析。现有 gshare 配置为 8 bit 历史、256 项 2 bit 计数器 PHT、16 项全相联 BTB（轮转替换）；v1 的新参数见第 7 节。

| 项目 | 现状 | 证据 |
| --- | --- | --- |
| BTB 分配 | **所有条件分支都分配**，无论实际是否跳转：S3 的 miniDecode 把每条条件分支标为 BR，后端对每个 BR 写 BTB | `BreezeFrontend.scala:478-483`、`BreezeBackend.scala:636-644` |
| BTB 的 `taken` 字段 | 写入但预测时不使用；条件分支方向只看 PHT，JAL/JALR 一律视为跳转 | `BreezeBTB.scala`、`BreezeFrontend.scala:232-245` |
| 全局历史（GHR） | 只在后端 EXE 解析条件分支时移入实际方向；所有条件分支都记录，包括 BTB 未命中的 | `BreezeBackend.scala:643`、`BreezeFrontend.scala:335-341` |
| GHR 检查点 | S2/S3 有 `ghrSnapshot` 寄存器随流水传递，但没有任何读者 | `BreezeFrontend.scala:396`、`431` |
| PHT 训练 | 用预测时记录的 `phtIdx`，预测与训练访问同一表项 | `BreezeBackend.scala:631` |
| RAS | 无。JALR 只靠 BTB 记住上一次的目标，且只在预测错时更新 | — |

**问题：**

1. **BTB 被不跳转的分支占用。**从不跳转的分支不需要 BTB（默认顺序取指就是对的），却占用 16 项中的位置，把跳转分支挤出去。
2. **历史滞后且滞后量不固定。**S1 查 PHT 时，S2、S3、fetch buffer、ID 中的分支尚未解析，不在 GHR 里；在途分支数随取指与停顿变化，同一条分支每次看到的历史缺失位数不同，PHT 表项相互干扰。
3. **函数返回几乎总是预测错。**同一函数被多处调用时，BTB 中的返回目标只对上一个调用者有效，错误要等到后端 EXE 才重定向。

## 2. 改动总览

| 改动 | 作用 | 位置 |
| --- | --- | --- |
| ① BTB 只为跳转分支分配 | 16 项全部留给需要目标地址的分支 | BTB 内部更新条件 |
| ② GHR 在 S3 推测更新，后端重定向时由检查点修复 | 历史只缺 S2/S3 中的一两条，几乎固定；且包含全部条件分支 | 前端 S3、重定向路径 |
| ③ 新增 8 项 RAS，在 S3 推测压栈/弹栈；S1 借助 BTB 的 RET 类型直接用栈顶预测返回 | 返回通常在 S1 就预测正确，不产生气泡 | 前端 S1、S3、重定向路径 |
| ④ L1I 顺序下一行预取 | 顺序执行的代码段不再每行都 miss | L1I |
| ⑤ 预测器参数调整 | BTB 32 项、PHT 1024 项、10 bit 历史 | BTB、PHT |

①和②配合：**进入 BTB 的分支**（只要跳转过的）与**进入历史的分支**（全部条件分支，由 S3 miniDecode 识别）彼此独立，BTB 只分配跳转分支不会使历史漏记不跳转的分支。

全部一次实现，各带一个配置开关（`btbTakenOnly`、`speculativeGhr`、`rasEntries`（0 表示关闭）、`s1ReturnPredict`、`icacheNextLinePrefetch`），默认全部打开，便于逐项对比测量。

## 3. ① BTB 只为跳转分支分配

- 条件分支只在**实际跳转**时分配新表项；实际不跳转时，若该分支已在 BTB 中则更新该表项，否则不分配。条件为 `update.taken || updateHit`，在 BTB 内部判断。
- 不在 BTB 中的条件分支在 S1 按顺序取指，等价于预测不跳转。它在 S3 仍被识别，进入历史（第 4 节），后端照常训练 PHT。
- JAL 照常分配。
- **返回指令（第 5 节的 pop 类 JALR）以 RET 类型写入 BTB**，目标字段不使用，供 S1 识别返回（第 5.4 节）；其他 JALR 维持“预测错时更新”。
- 删除 BTB 表项中不再使用的 `taken` 字段。

## 4. ② 全局历史：S3 推测更新与检查点修复

### 4.1 推测更新

- 当 S3 中的指令被 miniDecode 识别为条件分支、并被 fetch buffer 接收时，把它的**预测方向**（`s3_finalPredTaken`）移入 GHR。每条指令只更新一次，S3 因 fetch buffer 满而停住时不重复更新。
- JAL、JALR 不进入 GHR。
- S1 用当时的 GHR 计算 PHT 索引，与现在相同；索引随指令带到后端用于训练，所以预测与训练仍访问同一表项。
- 后端不再发送 `ghrUpdate`，只保留 PHT 训练。

### 4.2 检查点

每条指令随 `FrontendPredInfo` 携带 **GHR 检查点**：该指令在 S3 更新 GHR 之前的值（10 bit）。复用现有、未被使用的 `ghrSnapshot` 寄存器链，接入 fetch buffer 与后端。

### 4.3 修复

后端以指令 I 为重定向点发起重定向时，I 之后的指令全部被冲掉，GHR 恢复为“I 之前的历史，加上 I 自身已执行的条件分支结果”：

| 重定向原因 | GHR 恢复值 |
| --- | --- |
| I 是条件分支，方向预测错 | `Cat(检查点_I, I 的实际方向)` |
| I 是条件分支，方向对但重定向（如目标错） | `Cat(检查点_I, I 的实际方向)` |
| I 已执行完成后发起的其他重定向（JALR 目标错、FENCE.I、SFENCE.VMA、satp 写、xRET 等），且 I 不是条件分支 | `检查点_I` |
| I 在执行前被取代（I 本身异常，或在 I 之前接受中断） | `检查点_I` |

S3 的快速重定向发生在顺序路径上，此时 GHR 已与 S3 之前的指令一致，不需要修复。

后端的重定向输出因此需要带上：重定向点的 GHR 检查点、是否包含 I 自身的分支结果、I 的实际方向。

## 5. ③ 返回地址栈

### 5.1 识别规则

按 RISC-V 规范对 JAL/JALR 的提示约定，link 寄存器为 x1 或 x5：

| rd 是 link | rs1 是 link | rd 与 rs1 相同 | 动作 |
| --- | --- | --- | --- |
| 否 | 否 | — | 无 |
| 否 | 是 | — | pop（返回） |
| 是 | 否 | — | push（调用） |
| 是 | 是 | 否 | 先 pop 再 push |
| 是 | 是 | 是 | push |

JAL 没有 rs1，rd 为 link 时 push。push 的返回地址为 `pc + instLen`，压缩指令为 `pc + 2`。识别使用 S3 中已展开的指令，压缩形式的 `c.jal`、`c.jalr`、`c.jr` 由此自动覆盖。

### 5.2 预测与更新

- RAS 在 S3 推测更新，时机与 GHR 相同：指令被 fetch buffer 接收时执行 push/pop，每条指令一次。
- S3 识别出 pop 类 JALR 时，以栈顶作为预测目标；若与 S1 的预测不同（例如该返回尚未进入 BTB，S1 按顺序取指），发起 S3 快速重定向，约 2 拍气泡，比后端 EXE 重定向的代价小得多。
- 深度 8 项，环形实现：溢出覆盖最老项，下溢时栈顶无效，不发起快速重定向，交给后端处理。
- 后端照常校验 JALR 的实际目标，RAS 预测错只影响性能，不影响正确性。

### 5.3 检查点与修复

每条指令随 `FrontendPredInfo` 携带 **RAS 检查点**：该指令更新 RAS 之前的栈指针和栈顶值。后端重定向时按第 4.3 节相同的规则恢复：先恢复检查点_I，若 I 已执行且是 push/pop 类指令，再重新施加 I 自身的 push/pop。

只保存指针和栈顶：错误路径上的 push 可能覆盖栈顶以下的表项，修复后偶尔预测错，但保存栈顶已覆盖“错误路径上先 pop 再 push”这一最常见的破坏情况。

### 5.4 S1 阶段预测返回

S1 只有 PC、还没有指令，靠 BTB 告诉它“这个 PC 是返回”。RAS 的更新点仍留在 S3，S1 只读不写，检查点与修复规则不变。

- BTB 命中且类型为 RET 时，S1 以“当前栈顶”作为预测目标。
- **旁路：**S2、S3 中可能有已被预测、但尚未在 S3 更新 RAS 的指令。若其中有 push 类指令，S1 使用最年轻那条的 `pc + instLen` 作为栈顶；若其中有 pop 类指令，S1 不预测（按顺序取指），由 S3 处理。后一种情况只出现在返回紧跟返回时，很少见。
- S3 照常更新 RAS，并校验 S1 的预测：不一致时快速重定向，与 5.2 节相同。
- BTB 别名误命中（S1 认为是 RET，S3 解码发现不是）同样由 S3 的校验纠正。

不采用“把 RAS 的更新点挪到 S1”的方案：那样 S3 快速重定向冲掉的 S1/S2 指令也要恢复 RAS，S1 已更新过的指令 S3 不能再更新，BTB 误命中时还要撤销，需要重做一套机制。

收益：每次返回省掉 S3 的约 2 拍气泡。返回大约每 50–100 条指令出现一次，预计 IPC 提升 1%–3%，以计数器实测为准。

## 6. ④ L1I 顺序下一行预取

- **触发：**demand miss 行 A 时，在 A 之后发出 A+1 的预取；预取缓冲命中行 B 时，发出 B+1 的预取，使连续执行的代码持续预取。
- **存放：**1–2 行的预取缓冲，不直接装入 L1I，避免污染。demand miss 时同时查预取缓冲，命中则 1 拍装入 L1I，不再访问 L2。
- **限制：**不跨 4 KiB 页（同页内物理地址加 32 B 即可，跨页需要重新翻译）；下一行的 PMA 不是可执行且可缓存时不预取；FENCE.I 清空预取缓冲，在途的预取返回后丢弃；后端重定向不取消在途预取，但返回的行只进预取缓冲。
- **协议：**预取是不登记的 Read，每个 L1I 至多 2 笔 Read 在途（1 笔 demand、1 笔预取），source 多 1 bit（D-cache 文档 3.1、4.6 节）。
- demand miss 与在途预取是同一行时，等这笔预取返回，不重复发请求。

## 7. ⑤ 预测器参数

| 项目 | 现状 | Rocket 默认 | v1 | 说明 |
| --- | --- | --- | --- | --- |
| BTB | 16 项全相联 | 28 项 | 32 项全相联，寄存器实现 | 约增加 2k LUT |
| PHT | 256 项，8 bit 历史 | 512 项，8 bit 历史 | 1024 项，10 bit 历史 | 放入 LUTRAM，资源很少 |
| RAS | 无 | 6 项 | 8 项 | — |
| L1I | 8 KiB | 16 KiB、4 路 | 16 KiB、4 路、32 B 行 | 与 L1D 相同 |
| L1I 预取缓冲 | 无 | — | 2 行 | — |

是否继续扩大 BTB/PHT（改为 SRAM 组相联）由可观测性计数器决定，见 [`observability-design.md`](observability-design.md)。

## 8. 接口变更

| 接口 | 变更 |
| --- | --- |
| `FrontendPredInfo` | 新增 GHR 检查点（10 bit）、RAS 栈指针（3 bit）、RAS 栈顶（VLEN）、push/pop 标记 |
| fetch buffer、后端各级寄存器 | 随指令携带上述字段 |
| 后端 → 前端重定向 | 带上重定向点的检查点、是否包含 I 自身的分支方向与 push/pop、I 的实际方向 |
| 后端 → 前端 `ghrUpdate` | 删除 |
| 后端 → BTB 更新 | 分配条件在 BTB 内部判断；返回指令以 RET 类型发送 BTB 更新 |

## 9. 验证与测量

- **正确性：**分支预测只影响性能，不得影响架构结果。随机程序覆盖：深层递归与 RAS 溢出/下溢、错误路径上的调用与返回、条件分支预测错后紧跟调用/返回、压缩指令的调用与返回、异常和中断发生在分支/调用/返回上，与参考模型逐条退休比对。
- **定向检查：**GHR 在每种重定向原因后的恢复值；S3 停住时 GHR/RAS 不重复更新；不跳转分支不分配 BTB 表项。
- **测量：**每打开一个开关运行 `sim/litex/run_gshare_regression.py` 和基准程序，记录误预测率与 IPC；计数器清单见 [`observability-design.md`](observability-design.md)。
- **预取：**FENCE.I 后不使用旧预取；跨页、不可执行区域不预取；demand 与在途预取同行时不重复请求。
