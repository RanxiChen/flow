# Flow/Breeze 硬件技能共用约定

本页供 `.agents/skills/` 中的项目技能按需读取。技能提供分析与执行方法；任务范围和设计权限来自用户指令及 [`agent.md`](../agent.md)。引入技能不意味着允许修改 RTL、启动构建、发布图件、烧板或委派其他 agent。

## 设计与实现依据

- 新版 Breeze 从当前目标和已达成的决定出发。旧实现提供历史或局部复用证据，不自动成为兼容约束。
- 使用用户指定的权威规格。MMU RTL 实现以 [`breeze-mmu-rtl-spec.md`](breeze-mmu-rtl-spec.md) 为准；其他模块按当前任务明确权威来源。发现冲突时标明来源与影响，不自动重写任一方。
- 讨论与评审任务保持分析范围；缺少实现时可以分析规范并标记实现映射待完成。不得把未决定的行为补成定案。
- 区分架构决定、当前 RTL、模块测试、系统集成、综合、布局布线时序、上板及软件运行证据。

## Chisel 与工具适配

- Breeze 使用 Scala/Chisel。分析源代码中的 `Module`、`Bundle`、`Enum`、`Decoupled`、存储器及寄存器；Verilog/SV 提取器仅用于匹配配置的生成 RTL，不用于解析 Scala。
- 记录生成 RTL 对应的源版本、参数、顶层和生成命令。生成代码是配置后的实现证据，不能替代原始设计规格。
- 结合具体接口确定保持规则。`Decoupled` 的类型本身不保证 `valid` 或 payload 在反压时保持；采用该约束需要契约依据。`Valid` 响应没有 `ready`，接收方必须有相应容量或前进保证。
- 第三方技能中的 RTL、SVA、Cocotb、XDC 和 Tcl 示例是参考模板。核对工具版本、语法支持、时钟/复位、握手、采样时机和环境假设后使用。
- 各工具按实际可用性选择；不因技能引用工具就自动安装依赖、更换测试框架或连接新服务。绘图可以在本地完成；硬件构建与验证按下一节执行。

## Alan 执行与证据

遵守 [`agent.md`](../agent.md)：本地编辑；需要硬件执行时，通过已授权的提交/push、Alan pull 流程同步，检查远端分支、HEAD、工作区和正在运行的任务后执行。本地不运行 `sbt` 编译、RTL 生成、硬件仿真或测试。Vivado/Vitis/形式验证等新增硬件执行也使用 Alan；工具缺失时说明缺项，分析与脚本准备仍可完成。

每份执行证据应绑定源版本或明确的工作区快照、配置/顶层、器件、工具版本、命令、约束、日志和返回状态；涉及随机性时保存 seed。仅在任务需要时生成对应构建。技能文件、JSON/XML、Python 辅助工具的语法检查和绘图结构检查可以在本地进行，它们不构成硬件验证。

## 并发机制与验证

评审时追踪正常路径、并发占用、冲突/反压、恢复/重查、异常/kill、不可撤销副作用和资源代价。涉及活性时列出环境的最终响应或公平性假设；画等待关系不能代替无死锁证明。

形式验证区分 BMC 深度、有界活性、归纳/无界证明、cover 可达性和 unknown/timeout。禁止用排除合法输入的假设获得通过；检查复位、可达性与假设空洞。仿真期望结果来自规范或独立模型，不从 DUT 逻辑反向复制。

时序结论来自匹配版本的报告。历史路径用于提出假设；综合和布局估计与 routed 结果分开。不同器件、配置、约束、工具或含 ILA 的构建不能未经说明直接比较。`1000 / (period - WNS)` 不是任意路径或整个设计的通用 Fmax 证明。

## 上游资源

项目适配后的 `SKILL.md` 是入口；`SKILL.upstream.md` 保留原始文本用于参考，按原技能根目录理解其中的资源路径，不执行其宿主专用调度或自动动作。`UPSTREAM.json` 记录固定来源及原入口散列；许可证与已有版权说明保留在各技能目录。第三方完整目录包含未验证的示例；安装通过不意味着这些模板、工具或硬件已得到验证。
