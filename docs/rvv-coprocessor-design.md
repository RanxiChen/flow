# Breeze RVV 向量协处理器设计

本文记录 Breeze 单核 RVV 配置的微架构决定，按讨论顺序逐节追加。只写用户已确认的决定；未确认的内容放在最后的“待拍板”。本文不定义 RTL 字段，不代表已经实现或验证。

相关文档：[`roadmap.md`](roadmap.md)、[`backend-pipeline-design.md`](backend-pipeline-design.md)、[`dcache-pipeline-design.md`](dcache-pipeline-design.md)、[`observability-design.md`](observability-design.md)。

## 0. 范围与工作方式

- RVV 只做在单核 Breeze 上，并且是一个**独立的 SoC 目标**，单独出比特流。四核产品配置不受影响。
- Breeze 集群已冻结的接口不改。RVV 需要的新东西放在协处理器或 SoC 外壳里；确实需要改 Breeze 接口的，逐条列出，由用户决定。
- 开发在独立分支 `feat/rvv-20261005`（worktree `/home/chen/leisure/flow-rvv`）上进行，与 Breeze v1 主线互不干涉，以后再合并。
- 在 FPGA 可用之前，只做软件和仿真工作。
- **指令集范围（本版本）**：功能上实现完整的 RVV 1.0，编译器生成的任何向量代码都能正确运行；性能上只优化热点路径（Q4_0/Q8_0 推理用到的指令），其余指令只保证正确，可以多拍、窄宽度执行。以后可能重新实现 RVV，不为此预留兼容性。
- 快路径清单见 3.7、3.8 节。R01（工作负载画像）已按用户要求停止，结论见 3.7 节。

## 1. 性能目标与上限

### 1.1 目标与衡量方式

- **主目标**：Qwen2.5-0.5B，量化格式为 Q4_0 和 Q8_0。**进阶目标**：Qwen2.5-1.5B Q4_0。1.5B Q8_0 加上 Linux 放不进 2 GiB，不做。
- 按 llama-bench 的方式分别报告解码（tg128）和预填充（pp128）的 token/s。同时报告实测的 DDR 流式读带宽，以及“达到带宽上限的百分比”。所用 GGUF 文件、各张量的量化类型、提交号和比特流都要写明。
- 模型从 SD 卡加载。**不做 PCIe**：推理期间的带宽来自板上 DDR，PCIe 只能加快一次性的加载。

### 1.2 上限估算

解码时每个 token 都要把全部权重读一遍。Qwen2.5 的词嵌入和输出层共享权重，所以按总参数量计。

| 配置 | 每 token 读取 | 5 GB/s | 10 GB/s | 15 GB/s |
| --- | --- | --- | --- | --- |
| 0.5B Q4_0（4.5 bit/权重） | 278 MB | 18 | 36 | 54 |
| 0.5B Q8_0（8.5 bit/权重） | 525 MB | 9.5 | 19 | 28 |
| 1.5B Q4_0 | 866 MB | 5.8 | 11.5 | 17 |

单位为 token/s，都是上限。三列分别对应 DDR4 800、1600、2400 MT/s 时估计的可持续带宽（按理论峰值的约 75–80% 估计，未经实测）。800 MT/s 的理论峰值为 6.4 GB/s，即 100 MHz 系统时钟下每拍 64 B。KV cache 是 GQA 结构，每个 token 只有 12–28 KB，可以忽略。实际 GGUF 文件比理想值大 15–25%；非矩阵运算估计再占 10–20%。

### 1.3 由上限推出的需求

| 需求 | 数值 | 结论 |
| --- | --- | --- |
| 向量访存宽度 | 800 MT/s 时 ≥ 64 B/拍，1600 MT/s 时 ≥ 128 B/拍 | 宽度做成参数（512 / 1024 bit） |
| 在途能力 | ≥ 带宽 × 延迟，约 2–4 KB | 向量访存单元有自己的流式读引擎，不能靠 cache miss 驱动；现有 L2 内存引擎（64 bit、2 读在途）差 10–30 倍 |
| 解码算力 | 每拍约 114 个 int8×int4 乘加（MAC） | 约 60 个 DSP，算力不是瓶颈 |
| 预填充算力 | 计算受限 | 靠更多 DSP 和权重复用提高，见第 3 节 |
| 采样与非矩阵运算 | 对 151,936 个 logits 做 argmax/top-k，标量核约 10 ms | RMSNorm、softmax、RoPE、SiLU、激活量化、采样都必须向量化 |

**解码性能由访存通路决定，算力只决定预填充。**

## 2. SoC 与内存系统

### 2.1 方向（已定）

- RVV 配置是一个**独立的单核 SoC**，不是在四核集群上加东西。标量核沿用 Breeze v1 的前端与后端，不另写标量核。
- 单核不需要多核一致性，所以**这个 SoC 不用 Breeze 的 L2 目录和四链路协议**。
- **标量 L1D 改为写直通（write-through）**，保留 L1I 和 L1D，**不设 L2**。不采用“完全不要 D-cache”：单核配置 LUT 余量很大，L1D 只占约 6k LUT，而没有 D-cache 会使标量 IPC 下降一个数量级。
- L1I、L1D（refill 与写直通流量）、VLSU、SD 卡 DMA 经一个交叉开关接 DDR 控制器；DDR 控制器放在**独立时钟域**，目标 1600 MT/s 以上。VLSU 的端口宽度是参数（512/1024 bit）。
- **不设专用“向量区”**：任何地址都可以被向量和标量同时访问，一致性全部由硬件保证，软件不需要知道。
- 参照 Ara（CVA6 写直通 L1D、无 L2、向量单元经宽 AXI 直接访问内存）。

### 2.2 一致性规则（微架构层面，细节待适配时确定）

| 情况 | 规则 |
| --- | --- |
| 向量 store 后，标量读同一地址 | VLSU 每写一行，向 L1D 发一个作废请求；写直通 L1D 中没有脏数据，只作废、不回写 |
| 标量 store 后，向量读同一地址 | 向量 load 发起前，等标量写缓冲中地址重叠的项写完（v1 可以等写缓冲全部写完） |
| 已提交但未执行完的向量 store 之后紧跟标量 load/store | 在途向量访存登记 PA 范围（跨步、索引按全地址）；标量访存在 L1D S2 与之比较，冲突时暂不判定 |
| 已提交但未执行完的向量 load 之后紧跟标量 store | 同上：范围表**同时登记在途向量 load**，否则年轻的标量 store 可能先改掉向量 load 尚未读取的数据 |
| SD 卡 DMA 写 | 与 VLSU 相同，作废 L1D 中对应的行 |
| AMO、LR/SC | 单核，在 L1D 本地完成；VLSU 与 AMO 同时访问同一地址视为软件错误 |

### 2.3 挂载方式：协处理器独立，核心按合同提供服务

**原则：**协处理器不假设标量核的内部结构（几级流水、L1D 如何翻译、写口如何仲裁）。它只定义一份**挂载合同**（2.4 节）：自己需要核心提供哪些服务、自己向核心承诺什么。Breeze 在重构时自行决定用什么方式满足合同。独立开发期间，测试平台按同一份合同扮演核心。

这份合同按 Breeze v1 已有的三类机制来设计，使 Breeze 只需复用已有类别，不需要新的提交规则：

| Breeze v1 已有机制 | 对应到协处理器 |
| --- | --- |
| 长延迟单元：EX 发起、WB `commit`/`killUncommitted`、结果带 rd 保持到被接收 | 指令发起、提交、作废、标量结果 |
| L1D 的 S2 判定：Done / Mshr / Exc / 暂不判定，WB 等判定后才提交 | 协处理器对每条指令按程序顺序给出一次**判定**，WB 等判定后才提交 |
| AMO / MMIO：WB 等实际结果，不提前提交；发出后不能取消，中断等它完成 | 串行执行类指令（复杂访存、异常恢复） |

**翻译由协处理器自己发起。**协处理器有一个翻译请求口（VA、读/写 → PA、PMA 或异常），由核心提供实现：可以是 dTLB 的第二个查询口、经 L1D 的只翻译请求，或者其他方式，由 Breeze 决定。PA 从不经过发起接口，因此不存在“EX 拿不到 S2 结果”的时序矛盾。

协处理器完成后，Breeze 侧预计需要的改动（届时逐条列出，由用户决定）：ID 粗译码 V 指令与 vsetvl*；WB 对 V 指令等待协处理器判定；提供翻译服务；标量访存经冲突查询口与在途向量访存排序；L1D 写直通、作废口、写缓冲排空信号。

### 2.4 挂载合同

字段宽度由参数决定。所有握手为 valid/ready，除非注明为单拍脉冲。

**(1) 发起（核心 → 协处理器）**

内容：原始 32 位指令码；标量操作数（rs1、rs2 或 fs1）；vl、vtype、vstart 快照；vxrm、frm；rd。

**容量合同：**协处理器接收一条指令（发起 fire）时，必须已经为它在 VIQ 中**预留一个位置**。即：未提交项数 + VIQ 已占用项数 < VIQ 容量时，才允许 ready。因此之后到达的、不可反压的 `commit` 永远有地方承接。

**(2) 判定（协处理器 → 核心）**

对每条已接收、**且未被作废**的指令，**按程序顺序恰好给出一次判定**；被作废的指令不再给出判定（作废规则见 (3)）：

| 判定 | 含义 | 核心的动作 |
| --- | --- | --- |
| `Ok` | 不会产生同步异常 | 可以提交 |
| `OkVl(newVl)` | fault-only-first 裁短：不陷入，vl 改为 newVl | 写 vl 后提交（协处理器在内部使用 newVl） |
| `Exc(cause, tval, vstart)` | 精确异常；协处理器已保证这条指令没有任何副作用 | 不提交，按陷入处理，写 vstart |
| `Serial` | 需要串行执行才能判定 | 见 (4) |

非访存指令可以在接收后的下一拍就给出 `Ok`。单位步长访存的快路径判定见 3.9 节。核心在 WB 等到这条指令的判定后才决定提交、陷入或进入串行执行；判定之前可以被 kill。

**(3) 提交与作废（核心 → 协处理器，单拍脉冲）**

`commit`：提交最老的未提交项，该项必须已经得到 `Ok` 或 `OkVl`。`killUncommitted`：作废全部未提交项。两者同拍到达时**先提交最老项，再作废其余**。被作废的指令永不写 VRF、永不发内存请求。

作废对判定和翻译的影响：

- 判定与 `killUncommitted` 同拍出现时，该判定**无效**：核心不使用它，协处理器把对应项当作已作废。kill 之后不再出现任何被作废项的判定；下一个判定一定属于 kill 之后接收的指令。
- 已握手的翻译请求不能取消：核心必须应答每一个已接收的翻译请求，与发起它的指令是否被作废无关。协处理器丢弃属于已作废项的响应；**一个请求编号在其响应返回之前不得复用**，所以迟到的响应不会被误认成新指令的结果（与 Breeze FPU 的 killDrain 是同一个问题）。
- 被作废项尚未发出的翻译请求不再发出。

**(4) 串行执行（双向）**

收到 `Serial` 后，核心在这条指令成为最老、且决定不接受中断时，发 `serialGo`（单拍脉冲）。从此刻起：

- 这条指令**不能再被 kill**（与 MMIO 相同），核心在它完成之前不接受中断；
- 协处理器先排空所有更老的向量操作，再逐元素执行；允许产生部分副作用（这是 vstart 机制允许的）；
- 协处理器最后给出 `Done`、`DoneVl(newVl)` 或 `Exc(cause, tval, vstart)`；核心据此提交或陷入。

比它年轻的指令在 `serialGo` 之前已在流水线中，仍是未提交项，照常可以被 kill。

**(5) 翻译服务（协处理器 → 核心 → 协处理器）**

请求：VA、读/写、请求编号；响应：PA、PMA（可缓存 / device）或异常原因，按请求编号返回。核心可以反压请求，延迟不固定。协处理器只在判定或串行执行期间使用这个口；翻译结果只用于当前指令，不缓存。

**(6) 标量结果（协处理器 → 核心）**

`vmv.x.s`、`vcpop`、`vfirst`、`vfmv.f.s` 等：rd、数据、写整数还是浮点寄存器；valid/ready，保持到被接收。只对已提交的指令给出。

**(7) 状态（协处理器 → 核心）**

排空（未提交区、VIQ 与全部单元为空）；vxsat 累积值；以后 FP 指令的 fflags 累积值（读写 fflags/fcsr 的 CSR 指令先等排空）。

**(8) 访存排序与一致性（双向）**

| 信号 | 方向 | 用途 |
| --- | --- | --- |
| 冲突查询 | 核心 → 协处理器 → 核心 | 核心用 PA、大小、读/写查询是否与**已提交、未完成**的向量访存冲突（3.9 节的三类关系）；冲突时核心让该标量访存等待。覆盖范围与查询时机见下 |
| 行作废 | 协处理器 → 核心 | 每个被向量 store 写到的 L1D 行，发一个作废请求 |
| 标量写已可见 | 核心 → 协处理器 | 已提交的标量 store 是否都已到达内存；向量访存在需要时等待它（v1：每条向量访存发出第一个请求前等待） |

冲突查询的合同：

- **覆盖整段生命周期**：一条向量访存从**提交那一拍**起（包括仍在 VIQ、访存队列、请求阶段等待的时候），到 load 的全部 R 数据进入返回缓冲、或 store 的全部 B 响应返回为止，都必须能被查到。提交当拍的查询也要命中，不能有空窗。
- **只匹配已提交项**：未提交的向量访存不参与匹配。否则一条比标量访存更年轻、已经预翻译的向量访存会让标量访存等待，而它自己又要等这条标量指令提交，形成死锁。
- **查询时机由核心保证**：核心必须在这条标量访存的所有更老向量指令都已提交之后再查询，例如在 WB/S2。更早查询会漏掉尚未提交的更老向量访存。
- 快路径访存在判定时已经得到 PA，所以每一条已提交的快路径访存都有 PA 区间；串行执行期间核心不执行年轻指令，不需要查询。

**(9) 内存口：**宽 AXI4 主口，带 ID，宽度为参数。

## 3. 协处理器内部组织

### 3.1 总体思路

协处理器是挂在标量核后面的**第二个执行核心**：只接收已提交的指令，自己译码，再发射到各运算单元执行。

| 决定 | 内容 | 理由 |
| --- | --- | --- |
| 译码位置 | **协处理器完整译码。** Breeze 只做粗译码：识别 V 指令、要读哪些标量寄存器、是否非法（含 vill）、有无标量结果，并在标量流水中执行 `vsetvl*` | 对 Breeze 已冻结的 ID 级改动最小；以后重做 RVV 不牵动 Breeze。Ara、Saturn 都是这样 |
| 只接收已提交指令 | 协处理器内部永远不回滚 | 沿用 MDU 的 commit/kill 接口 |
| 单元之间 | **允许越位**：年轻指令可以在另一个单元先执行、先完成 | 性能来自这里，特别是 VLSU 提前装载下一批权重，同时计算当前这一批（访存与执行解耦） |
| 单元内部 | **按程序顺序** | 向量指令每条占多拍，单元内乱序几乎没有吞吐收益 |
| 寄存器重命名 | **不做** | 瓶颈是 DDR 带宽，乱序无助于带宽；重命名要把 VRF 放大 1.5–2 倍，LMUL 寄存器组的映射也很复杂；协处理器没有回滚，不需要重命名提供的恢复能力 |

主流情况：Ara、Saturn、Vicuna、SiFive X 系列都是单元内按序、单元间并行；把向量 uop 放进 ROB 并做重命名的是乱序标量核（如香山昆明湖），代价高，不适合本设计。

### 3.2 结构

```text
Breeze EX ──发起──→ ┌────────────────┐  commit  ┌──────────────────┐
                    │ 未提交区+判定器 │ ───────→ │ 向量指令队列 VIQ  │
Breeze WB ─commit──→│ kill 时全部清空 │          │ 按程序顺序        │
       ─kill──────→ └────────────────┘          └────────┬─────────┘
                                                         │ 译码 + 按序分派，分配年龄号
           ┌────────────┬────────────┬─────────┴──┬────────────┬────────────┐
           ▼            ▼            ▼            ▼            ▼            ▼
        访存队列     整数 ALU     整数乘加       FP 队列     跨 lane 队列   扩展槽
      (load+store)    队列         队列                    (归约/置换/   (矩阵引擎,
                                                           mask/slide)    预留)
                 └──── 每个队列一个 sequencer：队列内按序，队列之间并行 ────┘
```

| 部件 | 职责 |
| --- | --- |
| 未提交区 | 存放已发起、未提交的指令，每项记录判定状态；容量为参数，不依赖核心的流水级数。`commit` 把最老一项移入 VIQ（位置在发起时已预留，2.4 节），`killUncommitted` 全部丢弃；同拍时先提交后作废 |
| VIQ | 已提交指令的缓冲，让标量核跑在前面继续执行循环控制和地址计算；“未提交项 + VIQ 占用”达到容量时发起端 ready 为低 |
| 判定器 | 按程序顺序为每条未提交指令给出判定（2.4 节）；单位步长访存的快路径预翻译在这里进行 |
| 译码与分派 | 完整译码；按程序顺序放入对应的单元队列，每拍至多 1 条；分配年龄号，供冲突检查判断新旧 |
| sequencer（每单元一个） | 把一条指令按 LMUL 和 VL 展开成逐拍的元素组操作，决定每拍读写哪个寄存器的哪一段。不在入口把 LMUL 拆成多条微操作 |
| 向量 → 标量结果 | `vmv.x.s`、`vcpop`、`vfirst`、`vfmv.f.s` 的结果经标量结果口写回 |
| 状态 | 排空信号供 FENCE、读 vxsat 的 CSR 指令使用；vxrm 随指令在 EX 带走，vxsat 在执行时累积 |

v1 的 load 和 store 共用一个访存队列，按程序顺序执行：GEMV 内循环几乎只有 load，分开两个队列的收益很小，还要多做一套向量内部的地址冲突检查。以后计数器显示有必要再拆。

### 3.3 越位规则

| 后来的指令 | 能否越过更老的在途指令 | 条件 |
| --- | --- | --- |
| 向量 load 越过更老的计算指令 | 能 | 它的目的寄存器不被更老的在途指令读或写（无 WAR、WAW） |
| 计算指令越过更老的 load | 能 | 与该 load 之间无寄存器依赖 |
| 同一单元内的任意两条指令 | 不能 | 按程序顺序 |
| 向量访存之间 | 不能 | 共用一个队列 |
| 标量访存与向量访存之间 | 按 2.2 节 | — |

单元间并行后，RAW、WAR、WAW 三类寄存器冲突都必须检查；只查 RAW 是错的（例如快的整数指令覆盖了慢的 FP 指令尚未读出的源寄存器）。检查方法与链接见 3.4 节。

### 3.4 记分板与链接

**记分板按寄存器记位，但掩码挂在每条在途指令上，并带年龄号**，不使用一张全局的忙位表。

| 项 | 规则 |
| --- | --- |
| 每条在途指令的状态 | 年龄号；**写掩码**、**读掩码**（每个向量寄存器 1 bit，覆盖 LMUL 寄存器组、mask 源 v0 与扩宽的两倍目的组） |
| 置位 | 分派时按指令的源寄存器和目的寄存器置位 |
| 清除 | 写完某个寄存器的全部元素组时，清除该寄存器的写位；读完时清除读位；指令完成时全部清零 |
| 检查 | sequencer 处理某个寄存器之前，只对**比自己老**的在途指令取掩码的或：RAW 查老指令的写位；WAR（我要写）查老指令的读位；WAW 查老指令的写位。命中则等待 |
| 链接 | 老指令写完一个寄存器、清除对应写位后，年轻指令就可以读这个寄存器，不必等整条指令完成。链接粒度为一个寄存器；DLEN < VLEN 时，一个寄存器包含多个元素组，粒度相应变粗 |
| 不按寄存器顺序推进的指令 | 归约、`vrgather`、slide、分段访存、扩宽类指令：写位在整条指令完成时才清除，读位在全部源读完时才清除，即不参与链接 |
| 访存请求与 VRF 写分开 | 上述检查只约束 VRF 的读写。VLSU 发送内存请求只依赖标量地址，可以提前发出，返回数据暂存在返回缓冲中，等检查通过后再写入 VRF。提前量由返回缓冲容量决定 |

**为什么不用一张全局忙位表**（每个寄存器一个 busy 位，分派置位、完成清除）：

1. 全局位不区分新旧。较老的慢指令（例如 FP 单元中读 v8 的指令）会看到较年轻指令置的写位，从而等待一条比自己年轻的指令，结果出错或死锁。
2. 只有写位就查不了 WAR。标量核按序读操作数，不存在 WAR；向量单元之间允许越位，必须查。
3. 只靠读计数器做 WAR 也会死锁：年轻的读者依赖写者（RAW），自己却增加了写者正在等待的计数。

把掩码挂在每条在途指令上，按年龄过滤后再取或，上面三个问题都不存在。全局忙位等价于“比我老的在途指令写掩码之或”。在途指令最多十几条，硬件代价是每条两个 32 bit 掩码，加上每个 sequencer 一组按年龄过滤的或门，合计几百个 LUT。这与 Saturn 的做法一致。

### 3.5 已知代价

- **双缓冲是性能优化，不是硬性要求。** 没有重命名，load 写 VRF 时要等更老指令读完同一寄存器（WAR）。但内存请求可以提前发出、数据暂存在返回缓冲中（3.4 节），所以 DDR 延迟主要靠返回缓冲掩盖；软件用两组寄存器交替可以进一步消除 WAR 等待。LMUL=8 时只有 4 个寄存器组，内核主循环多用 LMUL=4。
- **向量 → 标量结果延迟长。** 标量核要等所有相关的更老向量指令完成，可能几十拍。内核应把累加器留在向量寄存器里，一行算完才归约一次。
- **中断不等 VIQ 排空**，已提交的向量指令在后台照常完成，与 MDU 规则一致。

### 3.6 VRF 组织

**布局：内存顺序行。**每个向量寄存器按 DLEN 位切成 VLEN/DLEN 行，每行内的字节顺序与内存一致；lane 是行内固定的一段字节，只是物理切分（布局与时序），不影响语义，lane 数为参数。

| 对比 | 内存顺序行（采用） | 元素交错到 lane（Ara，不采用） |
| --- | --- | --- |
| 按不同 SEW 重新解释寄存器 | 无代价 | 需要重排 |
| 单位步长访存 | 只做非对齐旋转 | 还要按 SEW 重排字节 |
| 扩宽、收窄 | 跨 lane，用固定接线（字节 j → 2j），放在乘加单元的操作数级 | lane 内完成 |
| 适用规模 | DLEN ≤ 1024，满足本设计 | 适合 lane 数很大的设计 |

**端口。**不加处理时，同一拍最坏需要 9 读 4 写。热点循环（3.7 节）中实际同时出现的是：乘加读 2、FP 读 2；VLSU、乘加、FP 各写 1。VRF 深度只有 32×VLEN/DLEN 行，用 LUTRAM 实现：读口靠复制，代价低；写口代价高，靠分 bank。

| 手段 | 规则 |
| --- | --- |
| v0 影子 | v0 在触发器中另存一份，写 v0 时同步更新；掩码不占 VRF 读口 |
| 执行读口共用 | 整数 ALU、乘加、FP 共用一组 **4 个**执行读口，每拍按需动态分配，按年龄优先 |
| 读口复制 | 执行 4 + VLSU store 1 + 跨 lane 1，共 6 份读副本 |
| 写口分 bank | 按行号低 2 位分 **4 个** bank，每 bank 1 个写口；写者按 bank 仲裁，冲突时一方等 1 拍，之后自然错开 |

读口不能分 bank：同一条指令的几个源操作数同步推进，编译器分配的寄存器组通常按 8 对齐，每拍读的行落在同一 bank。写口来自不同指令，撞一次后就会错开；热点循环中同时写的有 VLSU、乘加（累加器）、FP 三路。

资源估计：4 bank × 6 份读副本 × 约 350 LUT，加上读写多路选择器，合计约 10–12k LUT，待综合确认，是综合时的重点检查项。bank 数与读副本数为参数。

**跨 lane 的指令。**

| 指令 | 做法 |
| --- | --- |
| 归约 | 跨 lane 单元逐行读入，行内加法树，行间累加 |
| slide | 按行读入，整行旋转，跨行时拼接相邻两行 |
| `vrgather`、`vcompress` | 慢路径，每拍一个或几个元素 |
| 扩宽、收窄 | 在乘加单元内用固定接线完成，不经过跨 lane 单元 |

### 3.7 热点内核算法

GEMV（y = W·x）**把行放在向量元素上，x 用标量广播**，热点循环中没有水平归约：

```text
vqdot.vx  vacc, vW, rs1      # vacc[r] += Σ_{j=0..3} W[r][k+j] * x[k+j]
```

- **指令序列与配置（VLEN=512 默认）**：一次 `vsetvli e32, m4`，vl = 64（64 行）；每 4 个 k：`vle32.v vW, (aW)` 读入 64 行 × 4 B = 256 B 打包权重（每个 32 位元素是一行的 4 个 int8）；`lw t0, (ax)` 读 4 个 x；`vqdot.vx vacc, vW, t0`。权重寄存器组 v8/v12 交替（双缓冲），累加器 v16；**不能用 vle8**：同样 vl = 64 的 vle8 只读 64 B。
- **Zvqdotq 语义**（固定采用 riscv/riscv-dot-product 仓库的一个提交，提交号由 R02 记录）：只定义 SEW = 32；每个 32 位源元素视为 4 个 8 位数，第 j 字节（小端，位 8j+7..8j）与 rs1 的第 j 字节相乘，4 个乘积与 vd 相加；结果按 2^32 取模回绕，不饱和、不置 vxsat。`vqdot` 两边有符号，`vqdotu` 两边无符号，`vqdotsu` 为 vs2 有符号 × vs1/rs1 无符号，`vqdotus.vx` 为 vs2 无符号 × rs1 有符号；以固定提交的原文为准，若有出入，以原文为准并在报告中注明。Q8_0 用 `vqdot.vx`（权重与激活都是有符号 int8）。
- 一条指令处理 64 行 × 4 个 k。块（32 个 k）结束时，vacc 中就是每行在该块上的 int32 部分和，直接做缩放：`y[r] += float(acc[r]) * dW[r] * dx`。
- 权重在加载时**重排**为“一组行交错、每行 4 字节（Q4 为 8 个半字节）一组”的格式，沿用 llama.cpp 在 ARM 上的 repack 机制（`q4_0_4x8` 等），写 RISC-V 版本。
- 上游的 RVV 内核沿 k 方向向量化、每块一次归约，VLEN 增大时指令数不变（R01 测得），不再使用。

按 DLEN=512、LMUL=4、DDR 每拍 64 B 估算：

| 内核 | 每 256 B 权重 | 每拍权重 | 能否跟上 DDR |
| --- | --- | --- | --- |
| Q8_0，标准指令 | vle32 + vqdot.vx（乘加 4 拍） | 64 B | 刚好跟上 |
| Q4_0，标准指令 | vle32 + vand + vsrl + 2×vqdot.vx（ALU 8 拍 ∥ 乘加 8 拍） | 32 B | 只有一半 |
| Q4_0，自定义 vqdot4 | vle32 + vqdot4（直接读打包半字节，64 位标量装 8 个 x；乘加 4 拍） | 64 B | 跟上 |

块缩放每“行 × 块”需要 3 个 fp32 操作（转换、乘、乘加）。Q4_0 每“行 × 块”只有 16 B，DDR 每拍送进 4 个，所以每拍需要约 12 个 fp32 元素操作：**FP 在热点路径上**，全宽时利用率约 75%，半宽即成为瓶颈。Q8_0 的需求约为一半。

### 3.8 运算单元划分

| 单元 | 指令 | 宽度 | 热点 |
| --- | --- | --- | --- |
| VLSU | 全部访存 | DLEN | 是 |
| 整数 ALU | 加减、逻辑、移位、比较、min/max、merge/mv、定点、收窄移位、mask 按位逻辑 | DLEN，1–2 拍流水 | Q4 标准路径用；用 vqdot4 后基本空闲 |
| 整数乘加 | vmul/vmacc/vwmul/vwmacc、**Zvqdotq**、**自定义 vqdot4**；慢路径：SEW=64 乘法、除法与取余（窄迭代除法器） | int8 每拍 DLEN/8 个乘加，int4 加倍 | 是，主力 |
| FP | fp32 FMA/加/乘/转换/比较/min/max，fp16↔fp32；慢路径：除法、开方、fp64 | 参数，**默认全宽** | 是（块缩放） |
| 跨 lane | 归约、slide、gather、compress、vcpop/vfirst、vmv.x.s | 窄 | 否 |
| 扩展槽 | 预留给以后用于预填充的矩阵引擎；仓库中的脉冲阵列届时评估 | — | — |

- **Zvqdotq** 为 RISC-V 的 4 路 int8 点积扩展（类似 ARM SDOT），热点路径主要使用标准指令。批准状态与 GCC/LLVM 支持的版本待核实。
- **自定义 vqdot4** 是乘加单元的一个操作码，与 vqdot 共用乘法阵列，不另设单元。半字节拆分是固定接线；Q4_0 的 `n−8` 等于 `n XOR 8` 后按有符号 int4 解释，没有额外开销。
- **DSP**：`.vx` 形式中 x 为全部元素共用，可用 Xilinx 的 INT8 打包技巧（一个 DSP 算两个共享操作数的乘法）；每拍 128 个 int8×int4 乘加约 64 个 DSP。
- **FP 全宽、不加融合反量化指令**：全宽约 8–11k LUT、30–50 个 DSP（估计）。单核配置面积充裕，缺的是工期和验证，所以用标准指令换取简单。
- ALU 与乘加分两个队列，使 Q4 标准路径中两者可以并行。
- 预填充估计：每拍 128 个乘加 × 100 MHz = 12.8 GMAC/s，0.5B 约 25 token/s；更高的预填充性能靠扩展槽中的矩阵引擎。

### 3.9 VLSU

VLSU 是**无 cache 的流式引擎**，不经过 L1D，经自己的 crossbar 口直连 DDR 控制器。

**翻译与精确异常。**一条单位步长访存最多访问 VLEN 字节（EMUL ≤ 8），VLEN ≤ 4096 时最多跨一个页边界，至多 2 次翻译。物理上两页不一定连续，所以跨页访问始终按两个独立的 PA 区间处理。

| 访存类别 | 判定 |
| --- | --- |
| vl = 0（或 vstart ≥ vl） | 不翻译、不访存，直接 `Ok` |
| **快路径**：不带掩码的单位步长 / 整寄存器访存，非 fault-only-first，vstart = 0 | 判定器经翻译口翻译 1–2 页；全部成功且非 device 时给出 `Ok`，PA 区间留在协处理器内部随指令进入 VLSU |
| 快路径的翻译出现异常或 device | 不直接报 `Exc`，改给 `Serial`：由串行执行按元素编号确定第一个故障元素，正确处理非对齐元素跨页的情况 |
| 带掩码、fault-only-first、vstart ≠ 0、跨步、索引、分段 | `Serial` |

串行执行（2.4 节 (4)）逐元素进行：被掩码屏蔽的元素不翻译、不产生异常；第一个故障元素若是元素 0（或 vstart 所指元素），给出 `Exc`；fault-only-first 下若是之后的元素，给出 `DoneVl` 裁短 vl。`Exc` 带 cause、tval（故障 VA）和 vstart；之前的元素已经完成，重新执行时从 vstart 继续。device 区仍报 access fault。

R02 只实现快路径与 vl = 0；`Serial` 判定要能正确产生，串行执行本身在后续任务中实现。

否决的方案：VLSU 自带 TLB、共享 PTW，在提交后翻译——异常不精确。

**请求生成与返回缓冲。**

| 部件 | 规则 |
| --- | --- |
| 拆分 | 单位步长按 AXI burst 拆分，不跨 4 KB；burst 长度为参数（建议 256–512 B） |
| 信用 | 发请求前先在返回缓冲中预留空间，R 通道永不反压，不会死锁 |
| 提前发 | 请求只依赖 PA，不等 VRF；WAR 只约束返回缓冲写入 VRF（3.4 节） |
| 多条 load 并存 | **请求阶段按程序顺序推进：一条 load 的全部请求发出后，即可开始下一条的请求。**更早几条 load 的数据接收与 VRF 写回独立继续。VLSU 因此同时保存多条 load 的描述、信用和写回进度，条数为参数。不能实现成“一条完全结束才开始下一条” |
| 返回缓冲 | BRAM。512 位宽需 8 个 BRAM36，深度几乎不额外花钱，默认 8–16 KB，可提前装载多批权重 |
| load 数据通路 | 返回缓冲 → 非对齐旋转（拼接相邻两拍）→ 按字节写使能写入 VRF；掩码与尾部 undisturbed 用字节写使能实现，不读旧值 |
| store 数据通路 | VRF store 读口 → 旋转 → AXI W 加 WSTRB，不做读-改-写 |
| 在途深度 | 至少带宽 × 延迟（估计 2–3 KB）；受 AXI ID 数和 crossbar outstanding 数限制，均为参数，上板实测后确定 |

**内存口。**L1I、L1D、VLSU、DMA 各占一个 crossbar 口，按 burst 轮转，标量 refill 优先；VLSU burst 不宜过长，以免标量 miss 等待一整个 burst。DDR 跑 1600 MT/s 时 DDR 侧为 12.8 GB/s，而 100 MHz 下 512 位口只有 6.4 GB/s，**要用上 1600 MT/s，VLSU 口需 1024 位**（参数）。

**向量访存之间的排序。**访存请求按程序顺序发出，但**按序发出 AXI 请求不等于按序访问内存**，所以重叠的访问需要显式排序。每条向量访存在**判定为 `Ok` 时**（此时已得到 PA）登记 1–2 个 PA 区间，带“已提交”标志；提交时置位，被作废时删除。跨步、索引访问登记为全地址。向量之间的排序按程序顺序检查所有更老的项；标量冲突查询只匹配已提交的项（2.4 节 (8)）。释放和检查规则如下：

| 关系（老 → 年轻），地址重叠时 | 年轻者等待 |
| --- | --- |
| store → load | 老 store 的全部 B 响应 |
| load → store | 老 load 的全部 R 数据已进入返回缓冲 |
| store → store | 老 store 的全部 B 响应 |

load 的区间在全部 R 数据进入返回缓冲后释放；store 的区间在全部 B 响应返回后释放。不重叠时互不等待：不让所有 load 都等 store，否则每组行写回 y 后都要空等一次写延迟。同一张区间表也服务 2.4 节 (8) 的标量冲突查询。

v1 的 AXI 内存模型按序返回；若实现使用多个 AXI ID 且下游可能乱序返回，VLSU 必须按 ID 归还数据，并有对应测试。

**向量 store 与 L1D。**每写一行向 L1D 发作废请求。L1D 每拍处理 1 个、行 32 B 时，向量 store 带宽上限为每拍 32 B；LLM 中 store 很少，可以接受。

**计数器**（接入 `perf`）：读写字节数；返回缓冲占用；按原因分的停顿（WAR、store 重叠、信用、AXI）；作废请求数；慢路径指令数。

### 3.10 参数

VLEN、DLEN、lane 数、各单元宽度与流水深度、队列深度、VRF bank 数与读副本数、返回缓冲容量、AXI ID 数与 burst 长度、内存口宽度，全部由同一个配置入口给出，其余模块由它推导，并有非默认配置的冒烟测试。
