# Breeze RVV 向量协处理器设计

本文记录 Breeze 单核 RVV 配置的微架构决定，按讨论顺序逐节追加。只写用户已确认的决定；未确认的内容放在最后的“待拍板”。本文不定义 RTL 字段，不代表已经实现或验证。

相关文档：[`roadmap.md`](roadmap.md)、[`backend-pipeline-design.md`](backend-pipeline-design.md)、[`dcache-pipeline-design.md`](dcache-pipeline-design.md)、[`observability-design.md`](observability-design.md)。

## 0. 范围与工作方式

- RVV 只做在单核 Breeze 上，并且是一个**独立的 SoC 目标**，单独出比特流。四核产品配置不受影响。
- Breeze 集群已冻结的接口不改。RVV 需要的新东西放在协处理器或 SoC 外壳里；确实需要改 Breeze 接口的，逐条列出，由用户决定。
- 开发在独立分支 `feat/rvv-20261005`（worktree `/home/chen/leisure/flow-rvv`）上进行，与 Breeze v1 主线互不干涉，以后再合并。
- 在 FPGA 可用之前，只做软件和仿真工作。
- **指令集范围（本版本）**：功能上实现完整的 RVV 1.0，编译器生成的任何向量代码都能正确运行；性能上只优化热点路径（Q4_0/Q8_0 推理用到的指令），其余指令只保证正确，可以多拍、窄宽度执行。以后可能重新实现 RVV，不为此预留兼容性。
- 快路径清单由 [`tasks/R01-rvv-workload-perfmodel.md`](tasks/R01-rvv-workload-perfmodel.md) 的测量结果决定。

## 1. 性能目标与上限

### 1.1 目标与衡量方式

- **主目标**：Qwen2.5-0.5B，量化格式为 Q4_0 和 Q8_0。**进阶目标**：Qwen2.5-1.5B Q4_0。1.5B Q8_0 加上 Linux 放不进 2 GiB，不做。
- 按 llama-bench 的方式分别报告解码（tg128）和预填充（pp128）的 token/s。同时报告实测的 DDR 流式读带宽，以及“达到带宽上限的百分比”。所用 GGUF 文件、各张量的量化类型、提交号和比特流都要写明。
- 模型从 SD 卡加载。**不做 PCIe**：推理期间的带宽来自板上 DDR，PCIe 只能加快一次性的加载。

### 1.2 上限估算

解码时每个 token 都要把全部权重读一遍。Qwen2.5 的词嵌入和输出层共享权重，所以按总参数量计。

| 配置 | 每 token 读取 | 5 GB/s | 10 GB/s | 15 GB/s |
| --- | --- | --- | --- | --- |
| 0.5B Q4_0（4.5 bit/权重） | 278 MB | 18 | 36 | 54 |
| 0.5B Q8_0（8.5 bit/权重） | 525 MB | 9.5 | 19 | 28 |
| 1.5B Q4_0 | 866 MB | 5.8 | 11.5 | 17 |

单位为 token/s，都是上限。三列分别对应 DDR4 800、1600、2400 MT/s 时估计的可持续带宽（按理论峰值的约 75–80% 估计，未经实测）。800 MT/s 的理论峰值为 6.4 GB/s，即 100 MHz 系统时钟下每拍 64 B。KV cache 是 GQA 结构，每个 token 只有 12–28 KB，可以忽略。实际 GGUF 文件比理想值大 15–25%；非矩阵运算估计再占 10–20%。

### 1.3 由上限推出的需求

| 需求 | 数值 | 结论 |
| --- | --- | --- |
| 向量访存宽度 | 800 MT/s 时 ≥ 64 B/拍，1600 MT/s 时 ≥ 128 B/拍 | 宽度做成参数（512 / 1024 bit） |
| 在途能力 | ≥ 带宽 × 延迟，约 2–4 KB | 向量访存单元有自己的流式读引擎，不能靠 cache miss 驱动；现有 L2 内存引擎（64 bit、2 读在途）差 10–30 倍 |
| 解码算力 | 每拍约 114 个 int8×int4 乘加（MAC） | 约 60 个 DSP，算力不是瓶颈 |
| 预填充算力 | 计算受限 | 靠更多 DSP 和权重复用提高，见第 3 节 |
| 采样与非矩阵运算 | 对 151,936 个 logits 做 argmax/top-k，标量核约 10 ms | RMSNorm、softmax、RoPE、SiLU、激活量化、采样都必须向量化 |

**解码性能由访存通路决定，算力只决定预填充。**

## 2. SoC 结构

- 仍用 LiteX 作 SoC 外壳，另写一个 RVV target，复用 BIOS、SD 卡、UART、设备树和 `sim/litex` 流程。
- DDR 控制器放进**独立时钟域**，目标是 1600 MT/s 以上；LiteDRAM 在该速率下时序不满足时，再评估 MIG。
- DDR 前面接一个 crossbar：Breeze 集群用原有的 64 bit AXI `mem` 口；RVV 有自己的宽口（512/1024 bit），**不经过 L2**。
- 一致性方案见第 3 节（待讨论）。

## 3. 协处理器内部组织（原则）

- 少数几个**宽度为 DLEN** 的单元：向量访存（VLSU）、整数乘加/点积、ALU/移位/拆包、FP。每个单元每拍处理 DLEN 位数据。
- 调度器（sequencer）加记分板，让不同单元上的指令同时执行。记分板细到**元素组**，以支持链接：后一条指令不必等前一条整组写完。
- 稳态目标：向量访存单元每拍持续读入 DLEN 位，点积单元通过链接同时消费，两者都不停。
- VLEN、lane 数、DLEN、SEW、寄存器堆组织和自定义扩展，在后续各节逐项确定。
