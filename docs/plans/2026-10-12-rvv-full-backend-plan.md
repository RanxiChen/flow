## 执行组织

指令经完整译码与合法性检查进入未提交区。能够保证之后不会发生同步架构异常的算术指令，在核心 commit 后进入 VIQ，再按操作类型送 ALU、MAC、FP 或跨 lane 单元。可能访问内存并产生异常的指令，首版由 Serial 路径执行，保持核心最老指令所有权到 Done/DoneVl/Exc。

宽 ALU/dot 和连续访存硬件保留。完整功能优先由以下两类窄执行完成：一类是无访存的通用整数/置换执行引擎，一类是逐元素的串行访存引擎。向量 FP 首先使用向量侧独立的 64 位 FPnew 实例，复用算术实现；标量核自己的 FP 实例与 flush 所有权不改变。FP32 热点全宽流水属于后续性能阶段，不能把首版窄 FP 宣称满足原全宽性能决定。

### 操作数与寄存器访问

新描述符为 vs1、vs2、旧 vd、结果分别记录 EEW、有效寄存器组大小、基寄存器、起始元素、实际读写范围和数据类型。访存描述符另外记录地址模式、rs1、rs2/步长、索引 EEW/EMUL、NFIELDS、load/store/FOF/整寄存器/mask 访问类型。完整检查 vill、保留位、寄存器组对齐、范围、宽度、EMUL 上限、源/目的重叠和 v0 限制；非法编码在任何副作用之前给出 Exc，不以 assert 或默认 op 执行。

公共访问代理把逻辑元素映射为 VRF 行、字节或 mask 位。mask 结果为逐 bit 更新，要读改写旧目的行；不能只用 byte enables 覆盖包含其他 mask 位的整个字节。tail/mask/prestart、零长度、整寄存器和标量搬运各有独立规则，不能统一用 `vstart>=vl` 跳过所有指令。

先保持四 bank、六读副本。ALU/MAC/FP 共用四个执行读口，按年龄仲裁；store 和跨 lane 保持专用读口。窄引擎复用对应单元的访问代理，不为每种新指令复制全宽端口。写者增加时先集中仲裁到逻辑写口，保留每 bank 单物理写，不能把增加客户端等同于增加物理带宽。

VRF 读请求握手前取得相应结果容量，记录固定读延迟和返回归属。写入握手只是进入物理写寄存器；下一拍真正写 BRAM 后才解除依赖并发出完成事件。v0 影子与物理写同拍更新。实际时延从 RTL 和生成后的端口证据确定，不凭本方案新增任意流水拍数。

### 通用窄执行引擎

复杂但不会产生内存异常的操作，在程序序分派点先停止年轻向量分派，等待更老已提交操作完成，再取得 VRF 独占租约。不得等待包含自己及年轻未提交项的总 drained，否则可能自锁。

| 状态 | 正常动作 | 停顿与退出 |
| --- | --- | --- |
| WaitOlder | 固定本条年龄与读写组；阻止年轻向量分派，允许更老单元前进 | 更老 VRF 写、标量结果和状态事件全部完成后取租约 |
| Capture | 读取合法源组、必要的旧目的和掩码 | 等同步读返回，反压只保持已接受 token；全部捕获后进入执行 |
| Execute | 以一个或少量元素复用 64 位 ALU、宽中间乘积、迭代除法和专用置换控制 | 除法/FP 等可变时延按 token 等待；禁止提前释放源/目的 |
| Write | 合并结果和保留区域，按 VRF 行写出 | 等物理写完成；不按 write.fire 提前清位 |
| Finish | 给出标量结果及状态事件，释放本条所有权 | 接收方确认结果/状态后归还一次信用，再放行年轻分派 |

这个路径为合法重叠和非单调访问提供保守实现。默认 VLEN512 时，最大合法寄存器组为 8×64B=512B；最多三组输入与一组结果再加 64B v0 快照，保守数据容量为 2112B。具体 scratch 的 RAM 端口、分时访问与复用在 RTL spec 明确，不承诺该容量自动只占一个 BRAM。原寄存器保存、mask 和 prestart 规则同样覆盖该路径。

不能给每条冷门指令复制一个 512 位运算阵列。64 位 vmulh/vsmul 的中间结果需要完整高半/舍入信息，不能复用当前只保留低 64 位乘积的实现而丢位。

## 精确访存与异常

首版所有向量访存都可走串行路径。它不是“不支持”的非法指令回退，而是真正执行对应的 V 指令。尚不能证明安全的快路径留在硬件中用于回归，不进入完整功能产品的提交选择。

核心收到 Serial 时保留最老指令，建立串行屏障，保证年轻标量操作不能产生副作用，然后发 serialGo。协处理器排空更老向量操作和需要等待的标量写，取得串行访存所有权。对于不能预先得到连续 PA 范围的跨步/索引访存，期间保守阻塞标量访存冲突查询；不虚构一个覆盖全部地址的连续区间。已有被接收的年轻请求如何撤销/排空必须在挂载 spec 逐拍证明。

| 状态 | 所有权与动作 |
| --- | --- |
| AwaitGo | 等待核心成为最老并选择执行；此前可 kill，不访问内存 |
| DrainOlder | 允许更老单元、响应、PTW/refill 前进；阻止年轻副作用；排空条件不包含本条 |
| Element | 从 vstart 开始取活动元素、索引和字段；masked-off 元素不翻译、不访问、不产生异常 |
| Translate | 为当前元素/字段翻译并检查权限与 PMA；多页元素按既定平台规则处理 |
| Memory | 发起当前元素的读/写；store 先完成对应行作废及可见性条件，再等待实际响应 |
| Publish | load 数据真正写 VRF、store 得到完成响应后，推进可重启的位置 |
| Final | 正常 Done，FOF 裁短 DoneVl，或 Exc(cause,tval,vstart)；最终判定保持到核心接收 |

serialGo 后本条不能 kill；年轻未提交项仍可 kill。最终判定与初始 Serial 是两个阶段，mount 不能把第二个 verdict 当成下一条指令的判定。正常 commitD、串行完成和 kill 的信用归还分别记账，不能同条归还两次。

覆盖单位步长、跨步、索引有序/无序、分段、mask load/store、整寄存器和 FOF。首版无序索引访存也按元素序执行，作为合法的保守实现。分段 vstart 以 segment 为单位；要明确故障 segment 的字段可能已完成多少、重启是否允许重访问，不能把普通元素编号直接当字段序号。FOF 根据规格分别处理元素 0、后续活动元素异常、非零 vstart、零活动元素和中断，不能沿用一句“第一个访问故障都 trap”的泛化规则。

非对齐是否拆分或精确报 misaligned，由现行平台合同决定。device 区访问保留平台 PMA 策略；若禁止则精确报 access fault，而不是把合法向量访存当作非法指令。若允许 device 访问，要证明字段/元素顺序和不可重复副作用。

已有高速 VLSU 在 Ok 后把 AXI 错误作为 assert/fatal 的做法，不等于完整精确异常。恢复早提交快路径之前，必须给出匹配平台的后续无架构异常保证，或重新组织到可在退休前处理错误的完成路径。不能在较年轻指令已经提交后补写旧指令的 vstart 当作精确 trap。

翻译请求编号在收到响应前不得复用，包括 kill 后的迟到响应。串行完成、排空与 SFENCE 的条件覆盖仍在途的翻译、物理写寄存器、AXI response、标量结果和状态事件。主机/环境最终回应是活性前提；永久外部反压不是 DUT 自主前进保证。

## 浮点与状态

FP32/FP64 包含加减乘除、sqrt、FMA 各符号形式、比较、min/max、符号注入、分类、整浮点转换、FP32/FP64 扩宽收窄、标量广播/搬运及归约。vfrec7/vfrsqrt7 的近似语义和异常标志单独实现和验证，不能假定现有 FPnew wrapper 已提供它们。

CVFPU/FPnew 是算术实现复用点，向量操作仍需单独证明 NaN、sNaN、NaN boxing、舍入、RTZ/ROD 特殊转换、active 元素的 fflags 和非活动元素不产生异常。窄路径一次接受一个带指令/元素归属的操作，在结果空间不足时不继续发起；浮点归约先按规格允许的确定顺序完成，不以普通整数累加逻辑替代。

vxsat/fflags 只来自实际执行的活动元素。维护带归属的完成事件，在架构可见边界交给状态所有者；核心 CSR 读取/写入/清除与累积事件必须定义同拍先后，避免清除后旧事件重新置位。读取或修改相关 CSR 时先取得对应排空承诺；完成通知有反压就保持到被接收。向量浮点还需检查 mstatus.FS，不能只检查 VS。

## 当前结论

完整 V 1.0 有可实施的路径，主要工作是完整描述符与寄存器访问、串行访存/精确异常、浮点状态和核内提交，而不是 dot 算术。现有 storage、热点流水和真实 SoC 挂载可复用，资源总量支持继续做原型；完整功能与最终时序均需分阶段实证。实施从第 0 阶段的逐指令矩阵和 RTL 合同开始，在新分支推进，不介入正在进行的普通单核抓虫。
