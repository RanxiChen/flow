## Contract and implementation

The two return slots keep their existing capacity and non-flow cycles.
Registered `qValid || refillFault` controls the private payload write; the
registered tail selects its slot. Neither cancellation, response ready,
kill-qualified iTLB response valid nor late hit/PMP qualification controls
that write enable. `complete` retains its original qualification, and only
`(complete || refillFault) && !cancel` advances visible queue ownership.

| Requirement | Implementation and verification |
|---|---|
| A private write cannot overwrite a live stalled head | Assert spare capacity, unused reserved credit and distinct head/tail for one visible entry; directed full-queue/backpressure test |
| A miss candidate never becomes a visible result | Original complete/miss/refill rules retained; directed miss and refill-error test |
| Same-edge F1 completion and cancellation cannot leak a young window | Original kill/output masking and same-edge owner clear retained; test F2/global/fence cancellation with the real pipelined iTLB |
| F2 may consume its own head while canceling younger work | cancelYounger does not mask that head; directed test verifies its PC/data on the cancel edge |
| Same-address reuse cannot return a canceled fault or stale line | Directed canceled refill-fault retry and fence.i refill tests; existing frontend/refill regressions |
| No added hit stage or changed two-window capacity | Existing warm II=1 and mixed RVC/backpressure tests; explicit full-queue consume/reserve/replace test |

`qValid` and `refillFault` must not simultaneously own a private write.
Assertions check this and `count <= reserved`. Even cancellation-edge private
writes require an unused reserved slot. Payload writes have no SRAM installation,
refill request, training, architectural exception or response-valid side effect.
