## 1. 目标

## 2. 实现内容

### 2.1 参数

一个配置入口 `RvvParams`，所有模块的宽度、深度从它推导，不在模块中写死。至少包含：VLEN、DLEN、lane 数、VIQ 深度、各单元队列深度、VRF 写 bank 数与执行读口数、返回缓冲容量、AXI ID 数、burst 长度、内存口宽度。默认值 VLEN = DLEN = 512，其余由你决定。另做两组非默认配置的冒烟测试：VLEN = DLEN = 256；VLEN = 512、DLEN = 256。

### 2.2 结构（设计文档第 3 节）

| 部件 | 要求 |
| --- | --- |
| 顶层边界 | 按设计文档 2.4 节 (1)–(9) 全部信号组。**协处理器不得假设核心的流水级数或判定延迟**，只依赖合同中的握手 |
| 发起与容量 | 2.4 节 (1)：未提交项 + VIQ 占用 < 容量时才 ready，保证每个 commit 都有位置 |
| 判定器 | 2.4 节 (2)、3.9 节：非访存指令给 `Ok`；vl = 0 给 `Ok`；快路径访存经翻译口翻译 1–2 页后给 `Ok`；翻译异常、device、带掩码、fault-only-first、vstart ≠ 0、跨步/索引/分段给 `Serial`。按程序顺序给出 |
| 串行执行 | 本任务只实现到发出 `Serial`；收到 `serialGo` 时触发仿真断言“未实现” |
| 冲突查询、行作废、标量写已可见 | 2.4 节 (8)：冲突查询按 3.9 节区间表完整实现，从提交当拍起覆盖到完成，只匹配已提交项；行作废照常按行产生；每条向量访存发出第一个请求前等待“标量写已可见” |
| 未提交区、VIQ | 3.2 节；commit 与 kill 同拍时先提交最老项再作废其余（2.4 节 (3)） |
| 译码与分派 | 协处理器内完整译码；按序分派；年龄号 |
| 单元队列与 sequencer | VLSU、整数 ALU、整数乘加、FP、跨 lane 共 5 个队列，每个一个 sequencer，按 LMUL/VL 逐拍展开。FP 队列与 sequencer 可以只有框架（本任务不实现 FP 指令） |
| 冒险检查与链接 | 3.4 节：每条在途指令的读/写掩码 + 年龄号，按年龄过滤后检查 RAW/WAR/WAW；寄存器粒度链接；不参与链接的指令类别按 3.4 节处理 |
| VRF | 3.6 节：内存顺序行；v0 影子；4 个共用执行读口 + store 读口 + 跨 lane 读口；按行号低位分写 bank；字节写使能。bank 数、读口数为参数 |
| VLSU | 3.9 节的单位步长部分：跨页按两个独立 PA 区间；按 burst 拆分不跨 4 KB；发请求前在返回缓冲预留空间；请求不等 VRF，只有写 VRF 受 WAR 约束；**多条 load 并存**（一条的请求发完即可开始下一条）；非对齐旋转；掩码与尾部用字节写使能；store 用 WSTRB；三类重叠排序（store→load、load→store、store→store）；每写一行产生作废请求。v1 可以只用一个 AXI ID；若用多个 ID，必须按 ID 归还并测试乱序返回 |
| 标量结果口 | `vmv.x.s` 的结果经标量结果口返回，valid/ready，保持到被接收 |
| 计数器 | 3.9 节列出的 VLSU 计数器，加上各单元忙拍数、冒险停顿拍数（按 RAW/WAR/WAW 与单元分）；以端口形式引出即可，`perf` 接入以后再做 |

### 2.3 本任务实现的指令

| 类别 | 指令 |
| --- | --- |
| 访存 | `vle8/16/32/64.v`、`vse8/16/32/64.v`（单位步长、不带掩码，即快路径）。带掩码的访存按设计文档给出 `Serial`，本任务只检查判定，不执行 |
| 整数 ALU | `vadd.vv/.vx`、`vsub.vv`、`vand.vx`、`vsrl.vx`、`vmv.v.x`、`vmv.v.v`；前五条含带掩码形式 |
| 整数乘加 | `vmacc.vv`；`vqdot.vx`、`vqdotsu.vx`（Zvqdotq）。语义按设计文档 3.7 节；固定采用 riscv/riscv-dot-product 仓库的一个提交，提交号与编码写进报告 |
| 跨 lane | `vmv.x.s` |

其余指令在测试平台中不发送；协处理器收到未实现指令时触发仿真断言。`vsetvl*` 由测试平台（代替 Breeze）处理，vl/vtype 随指令送入。

### 2.4 测试平台

| 部件 | 要求 |
| --- | --- |
| 核心模型 | 代替 Breeze，**只通过挂载合同与协处理器交互**：每拍至多发起 1 条；收到该指令的判定后才 commit，判定到 commit 的间隔随机（0–3 拍）；标量指令按 1 拍占位，产生发射空泡；随机插入随后被 `killUncommitted` 作废的指令，包括与 commit 同拍的情况 |
| 翻译服务模型 | 页表由测试给出：虚页到物理页的映射**不连续**（相邻虚页映射到不相邻的物理页）；响应延迟与反压随机；可以注入缺页和 device 属性，用来检查 `Serial` 判定 |
| AXI 内存模型 | 数据宽度等于内存口宽度；读延迟、写响应延迟、R/W 反压均可配置和随机化；支持 WSTRB；按序返回 |
| 参照 | 用 Spike 运行同一测试程序，取得每条向量指令执行时的 vl/vtype、标量操作数和最终 VRF/内存状态；核心模型按这份记录送指令，结束时比较 VRF 与内存。**agnostic 元素（尾部与被屏蔽元素，在 vta/vma = 1 时）不参与比较**，因为规范允许保留旧值或写全 1。Spike 不支持 Zvqdotq 时，用 Spike 的扩展插件机制实现，并单独测试插件本身 |
| 断言 | 每拍至多一条写入同一 VRF 行；commit 到达时最老未提交项已得到 `Ok`；判定按程序顺序，每条未作废项恰好一次，被作废项没有判定、与 kill 同拍的判定无效；未应答的翻译请求编号不复用、属于作废项的响应被丢弃；未提交项 + VIQ 占用 ≤ 容量；被 kill 的指令永不写 VRF、永不发内存请求、永不发翻译请求以外的副作用；返回缓冲信用不为负；作废请求覆盖每个被写的行；重叠访存不违反三类排序 |

## 3. 测试程序

1. **定向**：每条已实现指令的基本用例；非对齐 base；带掩码的 ALU 指令；尾部 undisturbed；跨页的单位步长访问（两页物理不连续）；vl = 0；VIQ 只剩 1 个位置时连续发起与提交（容量预留）；commit 与 kill 同拍；kill 落在各种位置，包括翻译请求已握手、响应未返回时 kill 后立即接收新指令（迟到响应不得混入新指令）、判定与 kill 同拍；各类 `Serial` 判定（带掩码访存、注入缺页、device）。
2. **冒险与排序**：RAW 链接（vle 写完第一个寄存器后，vqdot 立即开始读）；WAR 越位（年轻的 vle 在更老的 vqdot 读完寄存器前不得写入，但内存请求已提前发出）；WAW；向量访存三类重叠关系（store→load、load→store、store→store）与对应的不重叠对照；多条 load 并存（前一条因 WAR 停住时，后一条的请求照常发出）；冲突查询口对在途 load、store 的命中与不命中，**包括已提交但仍在 VIQ/访存队列中、尚未发出请求的访存，以及提交当拍的查询**；未提交的向量访存不得被查询命中。
3. **GEMV 内循环**：按设计文档 3.7 节的指令序列：`vsetvli e32, m4`，vl = 64；每 4 个 k 一条 `vle32.v`（256 B）与一条 `vqdot.vx`，权重寄存器组 v8/v12 交替，累加器 v16；64 行 × K = 896；每 32 个 k 结束时 `vadd.vv` 累加到 v20（不做 FP 缩放）；最后 `vse32.v` 写回。结果与 Spike 一致。
4. **随机**：已实现指令的随机序列（随机 LMUL、vl、ALU 掩码、寄存器分配、访存地址重叠），判定到 commit 的间隔、翻译延迟、AXI 延迟和反压随机，至少 1000 个种子，与 Spike 比对。

P1–P5 的测量条件：第 3 节第 3 项的 GEMV 内核，默认配置；核心模型判定到 commit 间隔 0 拍、无随机 kill；翻译延迟 2 拍；AXI 无反压，只按单 ID 顺序返回。

稳态带宽的口径：从第一个读数据返回到最后一个读数据返回之间，VLSU 读入的字节数 ÷ 拍数 ÷ 每拍峰值字节数。**同时报告**：整个内核从第一条指令发起到最后一条 store 的 B 响应的总拍数，与“总读字节 ÷ 峰值”之比；内核结束时返回缓冲中尚未写入 VRF 的字节数。这样可以区分“读得快”与“消费得快”。

S1 的资源只代表 R02 子集：FP 与串行执行只有框架，不能当作完整 RVV 的面积。
