# BE2：后端控制解耦与 RVV 接入准备

2026-10-11，用户确认方向后由 Claude 编写；同日按 `BE2-ruling-proposal.md` 裁定 B1/B2/B3/C1/C2，修订了 R2/R4/R7、3.4 节、第 4 节 T14/T18–T20 和 S2。本任务书交给实现 agent（codex），**冻结规则与实现一次给出**：第 2 节结构规则和第 4 节合同修订是冻结项；其余实现细节由你决定，并写进报告。只有冻结项与实际结构矛盾时才停下报告，报告须附推导。

基线：`timing/soc3e-pipeline` 分支 `2051dd0`。

## 0. 现状与真正要解决的问题

### 0.1 已经具备的部分，本任务不改

现有后端为 ID/EX/MEM/PERM/WB/W2，见 `docs/backend-pipeline-design.md` 和 SOC-3e 修订。它**已经是早提交结构**：

- 所有指令在 WB 按序提交；
- MUL/DIV/FPU 和 Load miss 在提交后在后台完成，记分板跟踪尚未写回的结果；
- W2 普通写无条件完成；
- 不相关的年轻指令越过长延迟操作继续执行（P03/P06/P07 已覆盖）。

因此本任务**不改变**以下内容：提交点、记分板语义、精确异常语义，以及 RAW/WAW 规则。

### 0.2 真正的问题：WB 周围的全局控制还没有切开

| # | 现状（源码位置） | 问题 |

### 0.3 预期管理

这项重构从结构上消除上述控制锥，让以后每接一个新单元（RVV、矩阵扩展）都不再拉长 WB 判定锥。

它**不能单独解决 4 核布线**。4 核失败的主因是 LUT 用到 83% 和拥塞（见 SOC-3e 审核），而本任务基本不减少 LUT。因此 4 核只作为报告项，不作为门槛（见第 6 节）。

## 1. 目标与非目标

**目标**：在程序语义、内存顺序和精确异常都不变的前提下，做到以下几点：

- EX 之后没有全局保持；
- 提交和 kill 令牌寄存一拍后再发出；
- 执行单元容量在发射时预留；
- 结果由各来源自己保存，写口授权不反压进单元流水；
- "暂不判定"改为回放加独占发射；
- MDU/FPU/lateReg 统一成一种长延迟单元接口，并用一个协处理器桩验证这套接口，为 RVV 接入做准备。

**非目标**：双发射、乱序执行、重命名，以及改变 load-use 或其他已冻结的延迟。接入新前端另立 BE3。RVV 正式接入另立 R05'（见第 7 节）。

## 2. 结构规则（冻结）

| ID | 规则 |
|---|---|
| R1 | **EX 之后没有全局保持。** MEM/PERM 的级寄存器无条件推进，只允许 kill 清除 valid。WB 只在**独占指令**（R6）等待判定时自保持，此时 EX/MEM/PERM 必须为空，用断言检查。W2 保持现有规则 |
| R2 | **跨模块的提交和 kill 令牌寄存一拍（裁定 B1 修订）。** WB 判定同拍保留本地架构提交动作：记分板置位、CSR 和退休状态更新、普通结果捕获到 W2、后端内部级寄存器 valid 的作废，以及 L1D CPU S1/S2/S3 valid 位的作废（`s1Kill/s2Kill`）。这些本地动作不得新增通往执行单元推进或 ready 的组合控制链。送往 MUL/DIV/FPU/协处理器的 `commit`/`killUncommitted` 一律打一拍（`commitD`/`killD`）。前端功能重定向沿用已经寄存的 slow redirect；HPM 沿用 SOC-3c C4 的寄存规则 |
| R3 | **发射时预留容量。** ID 用寄存的 credit 计数决定 MUL/DIV/FPU/协处理器能否发射；EX 不读这些单元的 ready。EX 唯一保留的停顿源是 L1D S0 的接收（`l1d.req.ready`） |
| R4 | **结果自持，写口授权只用于出队。** 任何单元的流水使能都不能**同拍组合**依赖写口 grant（裁定 C1：允许单元因本地**寄存**容量用尽而暂停，例如 FPU 返回队列已满；禁止 grant 当拍反压到运算流水）。MUL 必须改为每拍推进，结果进入输出缓冲。写口仲裁的输入全部来自寄存器。grant 只做三件事：出队、清 busy、归还 credit。credit 归还可以在 grant 同拍生效，它与 busy 清除及写穿透到 ID 处于同一个锥，不另外增加路径。L1D `late.ready` 只读寄存状态 |
| R5 | **暂不判定就回放。** 指令到 WB 时，L1D 或协处理器还给不出判定，就给出 `Replay`。回放的处理：精确 kill 本条及所有更年轻的指令，从**本条 PC** 重新取指，并以独占方式重新发射。回放的那次尝试不得留下任何副作用 |
| R6 | **独占发射统一处理串行类指令。** 独占指令离开 ID 后，ID 停止发射，直到它离开 WB。独占指令包括两类：译码就能知道的串行类（FENCE.I、SFENCE.VMA、WFI、ESTOP、AMO、带 aq/rl 的 LR/SC），以及回放后重新发射的指令。独占指令在 WB 可以等待判定（R1 的唯一例外），L1D 或协处理器对它**只等待、不再回放**，回放第二次即断言失败 |
| R7 | **WB 判定锥的输入有界。** `wbCommit`/`wbKill` 的输入只能是：WB 级寄存器、L1D S3 判定、协处理器判定队首寄存器、中断/致命/停止寄存器、串行条件寄存器（drained/idle 的寄存版本；裁定 B3：原始状态变为就绪后，对应的 WB 串行动作允许晚一拍，见第 4 节 T18–T20）。报告逐项列出这些输入和逻辑级数。以后接入新单元时，最多只能在这个清单里增加"该单元判定队首寄存器"一项 |
| R8 | 保持现有规则：不为测试做特判；不放宽 golden、种子、规模、watchdog；单一配置入口 `BreezeClusterConfig`；默认关闭的新功能（协处理器桩）不影响默认生成的电路 |

## 3. 机制说明（实现细节由你决定）

### 3.1 寄存的提交令牌

- 单元在 `commitD` 到达那一拍，用寄存器标出"最老的未提交项"。结果输出条件写成 `valid && (committed || 本拍 commitD 命中最老项)`。`commitD` 本身是寄存器，可以在单元内部组合使用。
- 目标是 T04/T05/T16/P02/P08 的现值不变。如果推导结果必须加一拍，停下报告。
- `killD` 作废全部未提交项，**包括 WB kill 当拍 EX fire 的那一项**。由于 wbKill 同拍清掉 EX，`killD` 那一拍不会有新的 fire。同拍 commit 和 kill 的顺序仍然是先提交最老项，再作废其余项。
- 实现完成后删除 FPU 的 fire-under-kill 特殊处理，以及 SOC-3c D2 的同拍补丁。只有证明某段代码仍然必要时才保留，并在报告中说明理由。

### 3.2 发射预留

- 每类单元有一个 credit 计数器，表示"已发射但还没归还的项数"。ID 发射时扣减，写口 grant 时归还；被 `killD` 作废的项在 `killD` 拍归还。
- credit 计数器的容量等于单元内流水深度加输出缓冲深度，具体数值由你推导，要求 P02/P08 的吞吐不下降。
- DIV 的 credit 为 1。T07 的拍数不变，只是第二条 DIV 改为等在 ID，而不是等在 EX。合同措辞相应修改。

### 3.3 结果自持与写口

- MulUnit 改为每拍推进，在第 3 级之后接一个小输出缓冲，深度由 credit 推导。缓冲队首直接作为写口来源，保证无冲突时 T04 的 E+4 不变。
- lateReg 的 ready 只读寄存器，可以改成 2 项，也可以用其他等价做法。要求 T11/T12/T21/T22 不变，如果有变化，停下报告。
- 写口优先级（W2 > lateReg > DIV > MUL > FPU，加上协处理器桩）和饥饿保护阈值 3 都不变。协处理器桩排在最后。

### 3.4 回放与独占

- **回放属于 wbKill 类事件**，重定向目标是 `wb.pc`。复用现有的 slow redirect 通路。
- 回放时置一个寄存位 `soloArm`。之后从 ID 离开的第一条指令带上 `solo` 标记。在 soloArm 有效期间发生任何其他 kill，都清除 soloArm。
- `solo` 随请求送进 L1D S0（以及协处理器发起口）。L1D 看到 solo 请求时，只在 S3 等待、不给 Replay。
- 中断规则沿用现有规则：不可撤销的操作（例如 MMIO 已经发出）完成之前，不接受中断。
- **触发回放的原因**：现有 `undecided` 的全部原因，包括 TLB 等待、与 MSHR 同行、MSHR 已满、MMIO/uncached、LR miss，以及其他会让 S3 等待的条件；还有协处理器判定未到。每种原因单独计入一个 HPM 计数器。
- **L1D 内部操作占用 S3（`internal3.valid`）的冲突**：优先在 S0 接收时避开，即内部操作占用时让 `req.ready` 拉低，属于 R3 允许的 EX 停顿；不要让它变成频繁的回放。报告每种基准程序下的回放次数。
- **回放尝试不得留下副作用**：不写 PS，不重复分配 MSHR，不设置 reservation，不发出 MMIO；被回放的这条指令的本次尝试不产生预测器训练，Replay 同拍被杀的 EX 指令也不新建训练包（裁定 C2：现有 `train` 已排除 wbKill，此前已经合法发生的年轻投机训练沿用 SOC-3c D3，不撤销）。如果回放的尝试已经启动了 PTW 或 refill，让它继续完成，重新执行时会命中。

### 3.5 长延迟单元统一接口与协处理器桩

- 抽出一个统一接口 `LongLatUnit`：credit 发射、`commitD`/`killD`、结果输出（rd/bank/data/flags，valid 来自寄存器，保持到 grant）、drained 状态。MUL、DIV、FpUnit、lateReg 侧都用这个接口接入 Writeback。
- 协处理器另外有一个**判定源**：按程序顺序给出判定，队首是寄存器。如果指令到 WB 时判定还没到，就回放。
- **协处理器桩**（`Option` 参数，默认关闭）按 `rvv-coprocessor-design.md` §2.4 实现，范围如下：
  - 用一个保留的 custom 编码发起；
  - 判定延迟随机，种子可控；
  - 标量结果延迟随机；
  - 支持 Ok、Exc（写 vstart 的部分可以只给标记）和 Serial（按 R05 的临时规则，陷入非法指令）三种判定；
  - 遵守 §2.4(3) 的 kill 与判定同拍规则。

  这个桩只用于验证后端接口，**不是 RVV**。桩关闭时，默认 `BreezeClusterAxi` 生成的 Verilog 不能因为桩而变化。

## 7. RVV 接入规划

### 7.1 现状

- **协处理器本体**：在 `/home/chen/leisure/flow-rvv`（`feat/rvv-20261005`，`cc0be2f`）独立实现到了 R04。
  - 已有：整数/定点运算、单位步长访存快路径。
  - 独立 OOC 布线 WNS +0.221 ns，共 58k LUT。
  - 未完成：FP 没有实现，串行执行没有实现（Serial 临时按非法指令陷入），P1/P2 性能未达标，SB/VRF/ALU 三个单项超过面积预算。
- **挂载合同**：`rvv-coprocessor-design.md` §2.4 已经写定。

### 7.3 挂载合同各项在新后端上的落点

| §2.4 合同项 | 新后端机制 |
|---|---|
| (1) 发起与 VIQ 容量 | ID 侧 credit。**合同修订（Claude 裁定）**：增加一个由协处理器发出的 `creditReturn` 单拍脉冲，在 VIQ 项出队时发出；被 kill 的未提交项由核心在 `killD` 拍自行收回。发起口的 ready 不再参与后端推进 |
| (2) 判定 | 判定源的队首寄存器。指令到 WB 时判定未到，就按 R5 回放；独占重新执行时 WB 等待判定。非访存指令的判定在接收后一拍就到，不会触发回放；访存快路径第一次碰到 TLB miss 时可能回放一次 |
| (3) 提交与作废 | 使用 `commitD`/`killD`。在 wbKill 拍到达的判定，核心丢弃，因为对应项即将被作废；在 `killD` 同拍到达的判定，按合同本来就无效 |
| (4) 串行执行 | R05' 仍按临时规则陷入非法指令。以后实现 `serialGo` 时，直接复用独占发射（R6） |
| (5) 翻译服务 | dTLB 第二查询口，或与 dTLB 仲裁；复用现有 PTW。不得改变 L1D S0–S3 的时序 |
| (6) 标量结果 | `LongLatUnit` 的结果输出，写口优先级排在最后，受饥饿保护覆盖 |
| (7) 状态 | 使用寄存后的 drained 信号；FENCE 和读写 vxsat/vcsr 的 CSR 指令等待 drained |
| (8) 冲突查询 | 查询结果先寄存，再进入 WB 判定锥。冲突时回放；独占时等待。**保守规则**：查询发出时，只要还有更老的、尚未提交的向量访存在流水中，就视为冲突。这条规则同时消除"S2 查询早于更老向量指令提交"的漏查 |
| (9) 宽 AXI | 属于 SoC 侧，沿用 R05 原有方案（写直通 L1D、dataless home、交叉开关），只针对单核 RVV 预设 |
