# BE2 集中冲突与边界裁定提案

2026-10-11。状态：用户已集中采纳 B1/B2/C1/C2；B3 采纳并追加原始条件稳定性断言及证明要求。裁定已写入冻结任务书，提交 `027bda2`。此文件保留审查推导；实施以最新 `BE2-backend-decoupling.md` 为准，尤其 B3 附加条件。

## B1：R2 与 WB 本地提交动作

依据：任务书第 18 行保留提交点与记分板语义，第 55 行却只允许 WB 判定同拍影响后端和 L1D 的 valid。现有 WB 同沿还必须置 scoreboard busy、更新 CSR / 退休状态、捕获普通结果到 W2。

推导：MUL 在 E 发起、E+3 提交；E+4 WB 已离开，busy 必须接替流水中的依赖保护。直接把 busy 置位延后一拍会产生保护空窗，需额外桥接状态。把普通结果捕获延后一拍则改变 W2=E+4。它们都不是 R2 字面允许的 valid 动作。

建议替换 R2 的范围句：

> WB 判定同拍保留本地架构提交动作：记分板置位、CSR / 退休状态更新、普通结果捕获到 W2，以及后端内部级寄存器 valid 和 L1D CPU S1/S2/S3 valid 的作废。本地架构提交动作不得新增通往执行单元推进 / ready 的组合控制链。送往 MUL/DIV/FPU/协处理器的 commit / killUncommitted 一律寄存一拍；前端功能重定向经过已寄存的 slow redirect，HPM 保持已授权的寄存边界。

建议结果：保留 WB/W2 及架构提交拍数，只切开跨模块令牌。

## B2：R3 与未授权迁移的 T14

依据：R3 禁止 EX 读取 FPU ready，容量不足必须阻止 ID 发射；现行时序合同 T14 仍要求 FPU 入口满时保持 EX。任务书第 4 节只授权 T07 的等待位置迁移，没有列 T14；第 109 行要求其他 T/P 不变。

建议给第 4 节增加 T14 修订：容量不足时等待位置从 EX 改为 ID，入口容量在 ID 预留，已离开 ID 的请求须能在 EX 接受；保留 EX 接受后最早 E+1 向原始 CVFPU 发射、无停顿 II=1、两项无 flow/pipe 请求边界和 SOC-3e 返回边界。不得重复接受。

实现必须证明入口容量、tag 和 killDrain 的预留足以保证 EX 接受，不能用总 tag 数替代入口容量，也不能暗加未授权 FIFO。具体算法由实现者负责，若证明不能满足上述条件，再以反例报告。

## B3：R7 与 T19 / T20 原始状态同拍响应

依据：R7 要求 WB 串行条件使用 drained/idle 寄存版本。现有 T19 在原始 drained 于 D 变 1 时要求 D 当拍 redirect；T20 在原始 drained && mmuIdle 首次成立的 S 拍发 sfence，并在随后原始 idle 首次成立的 R 拍 redirect。SOC-3e 明确保留 T19/T20。

源码与测试：BreezeBackend 直接读取 io.l1d.drained / io.mmuIdle；BackendContractSpec 的 T19/T20 在拍内改变输入并检查当拍响应。对这些现有输入直接加 RegNext，会使对应响应晚一拍，不能同时宣称旧接口合同与旧测试未变。

建议优先满足 R7：明确寄存后的串行条件为 WB 唯一判断接口，允许原始状态变化到对应 WB 控制动作增加一拍，并在 T19/T20 中精确写明采样边界；T18 对已经稳定就绪的条件仍在 WB 当拍完成。SFENCE 两阶段顺序、排空、禁止年轻发射和禁止翻译请求均保持。

若选择严格保留相对于原始状态的旧 D/S/R，则必须在状态来源提供具有同样周期定义的已寄存接口并证明，不能在后端简单 RegNext 后更名周期来掩盖延迟。该替代方案尚未证明。

## C1：R4 与 S2 的结构检查边界

R4 的“任何单元流水使能不能依赖 grant”需明确是禁止同拍组合链。有限容量 FPU 仍可能因寄存的本地输出容量耗尽而暂停；已发生 grant 的历史必然会影响未来容量。建议允许本地寄存容量反压，禁止 grant 同拍组合反压到运算流水。MUL 按原要求每拍推进，以 ID 预留及足量输出存储保证安全。

S2 的禁止路径应明确检查级推进、宽 payload 使能、跨模块执行控制和前端功能控制；R2 明确允许的 valid 作废路径应单列检查，不应被当作仍存在全局 hold。结构报告须列出例外端点，不能以空查询结果冒充无路径证明。

## C2：Replay 无副作用与现有 D3 预测训练

任务书第 92 行禁止回放尝试训练预测器。现有 D3 是 EX 决定、下一拍无条件消费寄存训练包；较老访存后来在 WB Replay 时，年轻分支可能已训练。

建议无副作用范围指被回放本条的本次尝试，且 Replay 判定同拍被杀的 EX 指令不新建训练包；不要求撤销此前合法发生的年轻投机预测训练。保留 D3。若要求撤销所有年轻投机训练，则需另行迁移预测训练合同和实现恢复机制，不能当作本次普通代码整理。
