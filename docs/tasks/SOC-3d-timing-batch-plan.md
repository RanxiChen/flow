## 第一批：一起修改，一次验证，一次单核布线

1. **TLB/PMP**：PMP 保留在 S1；提前计算访问末地址低位和进位，预解码 PMP 配置，直接一热选权限，拆开 TLB 地址生成与权限判断。
2. **Cache**：CPU、refill、probe 分别计算授权资格，按原优先级汇合，缩短内部维护到阵列写使能的控制链。
3. **记分板**：ID 操作数直接与本拍实际完成目的比较，缩短同拍依赖解除；来源分类单独计算。
4. **浮点**：FP32 启用已有加法前寄存边界；FP64 在归一化与舍入之间新增边界，接受相应的内部延迟增加，保持一次最终舍入。

整数后端级数、L1D S0/S1/S2、提交点和一致性行为保持。本批将 TLB→S1 纳入修复范围，并同步候选 PA 旁带及浮点内部流水配置规格；其余拍数、golden 和断言含义不变。

合并为一个候选，相关功能门槛通过后，用同一最终 SHA 直接跑 tiny 完整布局布线，不逐项做对照实验。功能失败先修本批，不带已知失败进入物理验收。

## 第二批：第一批时序失败后，合并剩余瓶颈对应的修改

| 仍失败的路径 | 下一批试什么 |
| --- | --- |
| TLB→PMP | 重新安排权限检查边界，优先评估 S2 与 tag 并行；仍放不下再增加访存级并重新对齐 WB。 |
| FP 结果→ID/EX | 增加结果／反压隔离边界，按停顿传播与并发返回推导容量。 |
| Cache→阵列写使能 | 进一步拆开维护授权与阵列更新。 |
| FMA 内部计算 | 在最新报告指出的具体计算段再切一拍。 |

只做仍失败的对应项，合成下一候选。涉及新级、缓冲或协议时，先确定拍数、容量、取消和提交规则，再写 RTL；不直接给 ready/hold 延迟一拍。
