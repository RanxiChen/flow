# R01：RVV 工作负载画像与性能模型

本任务书交给实现 agent 执行。**本任务只做软件与仿真，不写任何 RTL，也不需要 FPGA。**它的结果用来决定 [`docs/rvv-coprocessor-design.md`](../rvv-coprocessor-design.md) 中的快路径清单、VLEN/DLEN、访存在途深度，以及是否加自定义扩展。

任务分两步：先做 W1 工作负载画像，**W1 回报后，等用户确认再做 W2** 性能模型。

## 0. 必须遵守的规则

1. **隔离**：只在分支 `feat/rvv-20261005` 上工作。不改 `design/`、`litex_wrapper/`、`fpga/`、`sim/`、`verification/` 中任何已有文件；Breeze v1 的工作由另一个 agent 在另一个工作区进行，不得触碰它的工作区和分支。新代码全部放在新目录 `rvv/` 下，新文档放在 `docs/` 下（文件名以 `rvv-` 开头）和 `docs/tasks/R01-*`。
2. **Alan**：按 [`agent.md`](../../agent.md)，本地改代码并 push，在 Alan 上 pull 后运行。Alan 上可能正在跑 T01 的任务：
   - 开始前确认 Alan 上已有的工作区、分支和正在运行的任务，**不得在 T01 使用的工作区中切换分支或修改文件**；为 R01 单独 clone 或建 worktree；
   - 长时间仿真用 `nice` 运行，同时运行的仿真进程数不超过 Alan 核数的一半，并在回报中写明。
3. **工具安装**：先盘点 Alan 上已有的 RISC-V 工具链、QEMU、Spike 及其版本。缺少的工具可以安装到用户目录下的独立前缀（例如 `~/opt/rvv-tools`）；需要 root 或系统级安装的，先列出来，等用户确认。
4. **证据规则**：每个数据都要附上：提交号、Alan 上实际运行的命令、日志或原始数据文件路径。没有运行过的写“未运行”；模型推算的数字一律标为“模型估计”，不得写成测量值。
5. **不改 llama.cpp 的内核**：W1 测的是上游现状。只允许为了能编译、能运行所做的最小修改，每处修改都列在报告里。重排格式和新内核是后续任务（W3）的内容。
6. **遇到本任务书没有覆盖的选择**，停下来列成问题提交，不要自行扩大范围。

## 2. W1：工作负载画像

### 2.1 正确性先行

1. 在 x86 主机上用同一 llama.cpp 提交和同一模型做原生运行，保存输出的 token id 序列作为参照。
2. RISC-V RVV 版和 RISC-V 标量版在 QEMU 上运行，token id 序列必须与参照完全一致；不一致时停下来报告，不继续统计。

### 2.2 统计方法

- 用 QEMU TCG 插件统计动态指令。可以使用 QEMU 自带插件，也可以在 `rvv/tools/` 下写一个小插件（C 语言）。插件需要做到：
  - 按函数符号归属指令数（以 ELF 符号表为准）；
  - 对向量指令按操作码分类计数，并记录执行时的 SEW、LMUL、VL；
  - 统计向量 load/store 的字节数，按单位步长、跨步、索引、分段分类。
- **预填充与解码分开统计**：在预填充结束、解码开始处设置分界（例如在 llama.cpp 中只加一个计数切换点，作为第 0 节第 5 条允许的最小修改并列出），或者用两次不同长度的运行相减，并写明使用的方法。
- VLEN 分别取 128、256、512、1024 运行，各统计一次。

### 2.3 需要回答的问题

| # | 问题 | 输出形式 |
| --- | --- | --- |
| Q1 | 解码每个 token 的动态指令总数；按函数分的前 20 名及其占比 | 表 |
| Q2 | 矩阵乘向量内核（Q4_0×Q8_0、Q8_0×Q8_0 的点积函数）中，每条向量指令的 VL 分布；每个 Q4_0/Q8_0 块用了多少条向量指令、多少条标量指令、多少条 `vsetvl*` | 表，按 VLEN 分 |
| Q3 | 内核在不同 VLEN 下是否走不同的代码路径（例如按 `vlenb` 分支），以及 VLEN 增大时指令数是否下降 | 表与源码位置 |
| Q4 | 向量指令按操作码的动态频度，标出归约类、扩宽乘加类、移位/与拆包类、访存类 | 表 |
| Q5 | 非矩阵运算（RMSNorm、RoPE、softmax/attention、SiLU、激活量化、采样/argmax、反嵌入等）各自的指令数与占比；其中哪些还是标量实现 | 表 |
| Q6 | 每个 token 经向量 load 读入的字节数，与模型权重大小对照，确认“每个 token 读一遍权重”这一假设 | 数值 |
| Q7 | 用到的 RVV 指令的完整清单（去重）；作为后续“快路径 / 只保证正确”划分的输入 | 清单 |
| Q8 | 标量版与 RVV 版的总指令数之比 | 数值 |

Q1–Q8 对 Q4_0 和 Q8_0 各做一遍，预填充与解码分开。

## 3. W2：性能模型（W1 确认后再做）

### 3.1 目的

给定协处理器参数，估算 Qwen2.5-0.5B 的解码和预填充 token/s，用来选参数。这是**分析加简单事件模型**，不是 RTL 级周期精确模拟。

### 3.2 模型输入参数

| 类别 | 参数 |
| --- | --- |
| 协处理器 | VLEN；DLEN；各单元（VLSU、整数乘加/点积、ALU/拆包、FP）的宽度与延迟；链接粒度（不链接 / 元素组）；归约指令的延迟与吞吐；每条向量指令的固定开销 |
| 访存 | 向量访存口宽度（B/拍）；最大在途字节数；DDR 持续带宽与读延迟（按 800 / 1600 / 2400 MT/s 三档的参数区间，DDR 带宽尚无实测，均标为假设） |
| 标量核 | 发射向量指令的速率（Breeze 为顺序单发射，每拍至多 1 条）；协处理器指令队列深度；标量循环开销取自 W1 的统计 |
| 工作负载 | W1 得到的各内核指令序列与次数；张量形状取自 W1 的张量清单 |

### 3.3 要求

- 每个内核分别算：访存时间、计算时间、标量发射时间，再按重叠规则合成；**重叠规则写成公式，写进文档**。
- 先用两个可以手算的极限验证：①访存口与在途能力无限时，结果应等于计算上限；②计算无限快时，结果应等于 DDR 带宽上限（与设计文档 1.2 节一致）。
- 参数扫描至少覆盖：VLEN ∈ {256, 512, 1024, 2048, 4096}；DLEN ∈ {256, 512, 1024}；在途字节 ∈ {512, 1 K, 2 K, 4 K, 8 K}；链接 ∈ {无, 元素组}；DDR 三档。
- 对上游内核与“假设内核每次处理 N 行交错块”（N ∈ {1, 4, 8}，只用模型推算，不写内核）分别给出结果，量化 W1 Q2 揭示的短块问题。
- 敏感度：对结果影响最大的 5 个参数，以及每个参数从扫描最小值到最大值时 token/s 的变化。

### 3.4 W2 产出

- `rvv/perfmodel/`：Python 实现（只用标准库、numpy 和 matplotlib），带一个能复现文档全部表格与图的命令。
- `docs/rvv-perf-model.md`：模型结构、公式、假设、验证结果、扫描结果与敏感度；每个数字标为“模型估计”。
- `docs/tasks/R01-report.md` 追加 W2 部分。
